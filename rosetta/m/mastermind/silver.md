# Mastermind

**Candidate: proofs likely to discharge automatically.** Every check follows from ranged subtypes, fixed array bounds and explicit input guards, and all unbounded loops sit in procedures where no termination proof is demanded. The main cost is new surface (stdin parsing, 2D arrays, string building), not proof difficulty.

## Failure paths to test

- **text parsing**: text that is not a number, a value outside the declared range, and empty text.
- **standard input**: end of input before the expected data, a line longer than the buffer, and bytes outside the accepted set.

## Approach

Settings and guesses are read as bounded lines, parsed with validation into ranged subtypes (colors 2..20, length 4..10, guesses 7..20, repeats yes/no), and re-prompted or rejected on bad input. The secret code is generated by a small LCG over a bounded range type, using a rejection loop for no-repeat mode with repeats forced when colors are fewer than code length. Each guess is validated for length and letters, scored with fixed-size arrays and for loops into X/O/- marks, stored in a 20 by 10 history array, and the history is reprinted after every guess. About 170 lines.

## Proof obligations to watch

- **overflow**: The deterministic code generator keeps its state in a bounded range type with a small modulus so the multiply-add cannot overflow.
- **index**: Hint matching uses nested for loops over a fixed 1..10 code range with the used length compared by guard, so indexes follow from loop ranges.
- **termination**: The no-repeat color selection and the read-until-valid-input loops are while loops inside procedures, which get no termination check, and the guess loop is bounded by the guess limit.
- **length**: Typed guess lines are bounded by a fixed-capacity buffer and rejected by an explicit length guard before copying into the code array.
