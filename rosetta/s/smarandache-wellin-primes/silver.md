# Smarandache-Wellin primes

**Candidate: proofs plausibly discharge automatically.** The required first three S-W primes (2, 23, 2357) and first three derived primes (the third is about 5.5e14) fit in a declared 64-bit-range integer, so only guarded loop-carried arithmetic needs care and no annotation is required. The big-integer stretch is optional and left out.

Position 291 in the [progression](../../progression.md#stage-9), in stage 9.

## Approach

Embed a fixed-capacity table of the first 100 primes generated by trial division, then walk the primes accumulating the S-W value in a bounded 18-digit integer type and testing each for primality by trial division with a d <= n / d guard until three primes are printed. A second pass tallies digit frequencies into a 10-element array, builds the derived number by appending each count's decimal digits with leading zeros skipped, and tests it the same way until three are found. Any capacity overflow or exhaustion of the table prints a specified rejection message instead of a result. About 130 lines.

## Proof obligations to watch

- **overflow**: Appending digits to the S-W value and to the derived value is loop-carried nonlinear arithmetic, discharged by an explicit guard before each multiply-add that rejects when the value would exceed a declared 18-digit range.
- **overflow**: The digit-frequency counters are loop-carried increments that need a guard against their declared upper bound, with exceeding it a visible rejection.
- **range**: The trial-division primality test keeps the divisor loop-carried and avoids d*d overflow by testing d <= n / d before each step.
- **index**: Prime-table and digit-count indexing must be guarded because the fill position is a loop-carried value, so the program checks it against the fixed table capacity before each store.
- **termination**: All while loops (prime generation, trial division, digit extraction) sit in procedures, so no termination check applies.
