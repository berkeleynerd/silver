## Failure paths to test

- **text parsing**: text that is not a number, a value outside the declared range, and empty text.
- **standard input**: end of input before the expected data, a line longer than the buffer, and bytes outside the accepted set.
- **exit status**: every failure outcome reaching its specified status, and success reaching success.

## Approach

Candidates are 3024 four-digit records with distinct digits 1..9 held in a fixed array with an alive flag, generated by nested for loops. A while loop in a procedure picks the first alive candidate (deterministic rather than random), prints it, reads a two-character bulls and cows line from stdin, validates it, and prunes candidates whose score against the guess differs via nested for loops. It ends on 4 bulls, on a single candidate remaining, or with a give-up message when none remain. About 170 lines.

## Proof obligations to watch

- **overflow**: Bull, cow and candidate counters are loop-carried so the prover knows only their subtype range; each increment is preceded by a guard against the subtype maximum that can never trigger on real data.
- **index**: The pool is a fixed array of 3024 candidates filled by four nested digit for-loops with distinctness checks, and the fill counter is guarded against capacity before each store.
- **termination**: The guess loop is a while loop in a procedure, which gets no termination check, and is also bounded by at most 3024 guesses.
- **range**: Parsing the typed bulls and cows into 0..4 digits requires explicit validation of length and character range, with invalid or inconsistent input (bulls+cows above 4) rejected visibly.
