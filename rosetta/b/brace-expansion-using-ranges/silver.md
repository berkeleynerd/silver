# Brace expansion using ranges

**Candidate: proofs plausibly discharge automatically.** Everything is bounded string scanning and integer stepping that guards and declared limits can cover, but the many loop-carried indexes and the capacity and overflow guards make the shape delicate, with no need for annotations.

Position 1150 in the [progression](../../progression.md#stage-20), in stage 20.

## Approach

The program embeds the ten test patterns as String constants in a fixed table and, for each one, scans bounded Character data to find the first complete brace pair, validates the contents as numeric or single-character ranges with an optional increment, and treats anything else as literal text. Counts and endpoints are held in bounded integers with digit-count caps, expansions are generated by a stepping loop into fixed-capacity line buffers (handling the minus-sign reversal and zero-padding), and several ranges are handled by iterating a nested index over the per-range counts rather than recursing. Emoji endpoints are treated as a bounded run of bytes compared as a unit, with each range's multi-byte endpoints expanded through a small fixed byte-sequence table, and all output goes through Put_Line. About 230 lines.

## Proof obligations to watch

- **index**: Scanning for braces, dots and digits uses for loops over the pattern's own range with a guard before every look-ahead character access, and output buffers are written only after a capacity guard.
- **overflow**: Numeric endpoints are parsed digit by digit with a cap on digit count (for example at most 6 digits) and rejected otherwise, so the stepping accumulator stays inside a declared Integer range.
- **termination**: Stepping loops live in procedures (no termination check), and the step is made positive by rejecting a zero increment before the loop.
- **length**: Every expansion is appended to a fixed-capacity bounded buffer with an explicit check that the output length and the product of counts for multiple ranges fit, with a specified rejection or literal outcome if not.
- **range**: Zero-padded formatting computes digits into a fixed-width buffer with width bounded by the parsed digit limit, so character positions stay in range.
