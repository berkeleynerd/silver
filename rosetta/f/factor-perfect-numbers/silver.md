## Approach

Every sum is guarded against a stated cap and a violation prints a rejection message. About 210 lines.

## Proof obligations to watch

- **overflow**: The sieve accumulates H(m) += H(d) in a loop-carried array element whose only known bound is its type, so each addition needs a guard comparing against a declared cap with a visible rejection outcome, which keeps all values under 2**62 comfortably since H(n) for n <= 30000 is about 1e8.
- **index**: Multiples m = d*k are generated by repeated addition under a while guard m <= N so indices stay within the array bounds without nonlinear reasoning.
- **index**: The explicit DFS stack depth is bounded by log2(48)+1, which needs an explicit guard before each push to prove the stack index in range.
- **termination**: All while loops are in procedures, which get no termination check, so no variant is needed.
- **other**: Stretch numbers beyond 29808 are optional and would need a larger sized cap and rejection path, so the program stops at the seventh term.
