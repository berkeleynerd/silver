Native `Source_ptr` copies a decoded input string (`gnat_ast.ml:1351–1355`).

interruption before `pop` can leave a raw pair, not a previously concatenated
filename. Repeated `mk_attrs` therefore does not iterate concatenation.

`Ident.create_loc_attr/get_loc_attr` adds/parses four integer fields but
preserves the filename suffix; raw location attributes from JSON have suffix
length at most U. Typing's location cutoff preserves the filename. Location
joins, clones and selected transforms copy positions or these attributes;
they do not concatenate filenames. Fixed `<dummy>` and empty names fit L.
The initial parser/driver path origins fit 180<=L in every row. Other
S-expression, model, interactive, extraction and frontend location producers

registers its parser/printers; it does not execute its unselected frontends.
Compiler assertion source filenames keep their accepted separate H=467 origin.

This gives an induction over **all strings offered for FileTags insertion**.
It does not require an atomic successful `Hstr.add; Hint.add; incr` sequence.

## Complete frontend frame and separately owned raw paths

Under the [prospective canonical protocol](retained-adapter-protocol-storage.md),
a positive OCaml ID has at most 19 decimal bytes. An S wire line needs at
most 22 bytes; an F wire line needs at most `Pc+19+29`, including LF and the
bounded canonical scalar fields. Empty-filename cancellation is smaller.
Hence M=Pc+48 bounds each complete frontend line. `read_lines` assembles
1024-byte chunks before `read_answer`; 1024 is not a frame cap. Splitting on
newlines and joining the filename's semicolon-separated pieces do not add
bytes beyond the original frame. Failed startup/connect, malformed streams
and a violated proxy framing/publication contract remain outside this result.
Backend C+11 filenames remain the backend owner's operand, not a Why client
pathname supplied by the canonical frontend.

There is one deliberate residual path domain. `Env.locate_library` constructs
candidate strings before filtering them through `Sys.file_exists`:

```
P_stat = max |Filename.concat dir (base ^ "." ^ ext)|
dir in actual immutable Env.get_loadpath env
base in {int, real, algebra, relations}
ext in {mlw, why, adb, gnat-json}.
```

The selected unique opened library has the unchanged installed provider
above. Other stat candidates can have longer spellings. The current source
configuration refers to generated Config.datadir, whose actual complete
default-loadpath value is not extracted by this packet. Therefore P_stat is
**not numerically discharged**, and this note makes no complete any-path or
raw path-construction/storage capacity claim. That separate owner must attach
the actual immutable loadpath and registered-extension set before using such
a claim.

OCaml `caml_sys_file_exists` returns false for invalid C-safe names or failed
stat (`runtime/sys.c:239–258`); it does not raise `Sys_error(candidate)`.
Allocation/asynchronous failure during construction or the primitive remains
possible and has its own scalar/save origin, not the candidate text. A
multiple-existing-file `AmbiguousPath` or `LibraryNotFound` belongs to Driver
preparation and its payload is dropped by the accepted parallel boundary;
there is no terminal scalar leaf that copies these raw probe strings. This
is a source argument, not suppression of all failures or an added success
assumption. Path-storage capacity remains separately open even when its
bytes do not enter terminal diagnostics.
