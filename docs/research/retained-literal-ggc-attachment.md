## Failure semantics and guards

The accepted native API requires its inherited predicates to be true. The
wrapper checks both upstream condition maps and the selected/core arithmetic
summaries before calling it. If any prerequisite is false:

- The native composer is not called; `selected_native_GGC_ledger` is null.
- `ggc_attachment.ledger_status` is `not_computed_upstream_arithmetic`, with
  explicit reasons. All 17 new predicates are null/uncomputed.
- Existing false predicates and their values remain in the failed lists;
  composite success and indexed-storage capacity are false.
- Count/page bounds remain null. Source/configuration/owner validation still
  runs and rejects genuine mismatches.

No flag is fabricated or promoted to enter the native API. A successfully
computed ledger with false local arithmetic instead has status `computed`,
boolean local predicates and a retained ledger, with composite capacity false.
These two states are deliberately distinct. Both condition maps and their
failed/unresolved lists are recomputed with `value is True` conjunctions;
uncomputed checks cannot count as successes.

The 17 new predicates retain the accepted 16-check native schema and its
capacity conjunction: reload normalized capacities, growth and individual
requests; CFG signed extent, unsigned growth, normalized capacities and
individual requests; second-unshare request sizes; signed `10000C <= INT_MAX`
hard-register usage; individual GGC order region; signed active-page index;
unsigned page-pointer capacity; each pointer backing span; association caller
product; and the established inherited-source premise. Names cannot replace
upstream keys and computed values must be booleans.
