# Selected literal-output native-build capacity

This is the complete native-only research composition for
[#145](https://github.com/berkeleynerd/silver/issues/145), within unfinished
[#119](https://github.com/berkeleynerd/silver/issues/119). The
[independent aggregate review](../reviews/review-literal-native-completion-20261019.md)
accepts implementation freeze `4f29a3bf85` without material findings. The
[executable evaluator](../evidence/retained-literal-native-completion-20261019/compose.py)
combines fresh actual-source results for the selected four-job native graph.
It does not implement a production launcher or change admission, the Oracle,
installed tools, or their pins.

The family remains one declaration-free Main/SPARK shell, one `with Silver_IO`,
C>=1 qualified literal Put/Put_Line calls and N>=0 null statements, with the
accepted lexical/trivia rules. Counts alone do not identify this family: the
existing recognizer consumes every actual source byte. This is neither the
complete current Silver grammar nor the proposed future language surface.

## Computable rule and source identity

The input is the retained selected-route descriptor and an actual source path.
Context validates frozen repository components, their transitive source and
installed configuration inputs, and the common compiler-shell source manifests.
The evaluator freshly invokes the [corrected register adapter](retained-literal-register-completion.md).
That route computes the full source identity/counts, frontend/interface
projections, emission, native invocation, fixed inputs and refined linker
rule. No retained Hello result supplies the capacity for another program.

Every one of its **408 current guards** is retained in both maps. In
particular, the current 51-owner GGC ledger and corrected collector arithmetic
supersede the older 50-owner ledger nested as history. Either a false or an
uncomputed value, or a false required summary, prevents the completion joins
and native success. Invalid source or a mismatching input/interface is an
error, never a success. `attach` is an internal join exposed for deliberate
mutation tests; the public `evaluate` API accepts no caller-supplied success
record or remainder-safe premise.

For a passing predecessor, parent, driver and binder each independently
reconstruct the invocation from the same raw bytes and require full equality
with the supplied graph. The parent and driver also return matching complete
graph identities. Ada completion verifies source/count/table/ALI ownership
joins against the freshly derived record and corrected conditions. The
predecessor uses512 pathname characters, hence513 bytes including NUL.
The child packets use the stronger512-byte envelope including NUL. The
aggregate freshly builds that stronger graph using the actual runtime paths,
then requires **whole-record equality** with the register graph after changing
only its top-level `path_bytes` scalar to512. Every execution and derived
interface field must remain equal. The fresh builder checks the stronger
bound; it is not inferred merely from the looser predecessor. The host page is
4096 bytes. This packet selects the canonical retained runtime route; a
different directory/configuration requires a corresponding fresh route
argument, rather than silently reusing this result. The binder API now passes
an optional runtime argument to its existing fresh builder, just as parent
and driver do; otherwise its default directory layout would differ. Its full
supplied-invocation equality check and all capacity arithmetic remain intact.

The complete native verdict is the conjunction of both current condition
maps, the additional component guards and every stage below: **475 conditions**
on the passing selected route. Twelve explicit
stage entries prevent an uncomputed component from becoming a successful
whole-native result. This Boolean is a source-derived **research capacity
rule under the stated interfaces**, not evidence that the future SPARK parent
has already been implemented or verified.

## Binder compiler and assembler composition

The actual invocation guarantees the generated OUTPUT binder has the retained
source family: only Main's eight-hex-digit checksum varies over uint32. Its
semantic read projection, ordinary requests and output object layout are
unchanged except the explicitly charged numeric/cache effects. The accepted
[checksum closure](../evidence/retained-binder-checksum-closure-20261018/review.md)
provides E=56,378 positive GGC requests, cumulative rounded allocation
B=5,167,732 and maximum rounded request262,144. B is below the first
collection threshold5,242,880 by75,148 bytes. This excludes actual marking
collections, not heuristic calls to `ggc_collect`.

The collector therefore needs at most E active pages. Its pointer capacity
is next_power_of_two(max(128,E))=65,536, each backing524,288 bytes. The
existing vector growth bound gives finalizer capacity
max(4,E,2*min(15,E-1),floor(3(E-1)/2)); check 31-bit capacity, unsigned
length/growth and individual 8+16*capacity / 8+32*capacity requests. Conservatively
using E for each finalizer kind is valid because each registration accompanies
a positive GGC allocation. The accepted numeric transfer permits at most
one extra Uint wrapper of16 bytes. Fixed ordinary semantic requests transfer
from the successful output binder compiler; common startup/argv/environment
is discharged separately above. These are individual representability and
fixed-success arguments, not a summed process-memory gate.

The assembler's new accepted source argument distinguishes zero's `.zero 4`
fragment from nonzero's signed32 decimal `.long`. Four retained executions
exercise the two request classes and decimal extremes. The source argument
covers every checksum; the samples alone do not. No bignum, symbol or fixup
is introduced by the operand. Its complete assembly is at most31,743 bytes,
1262 lines, maximum line87 bytes. This transfer uses the accepted startup
path/environment argument for the current invocation; the short capture's
`-S` command is not relabeled the production command.

The join requires the actual binder family to have16 sections,243 symbols,
134 relocations, alignment32, EH-frame224, text1278, allocated12,493 and file
upper17,952 bytes. Both checksum classes produce that interface, with only
four object data bytes changing. The linker accepts that family, not one
captured checksum object's hash. Fixed runtime inputs, library resolution,
relocation reach and output layout retain the current independently reviewed
source-sensitive bounds.

## Assurance boundary and remaining work

Every source argument is conditional on relevant installed behavior matching
the inspected tool sources/configuration, the selected Linux x86-64 ABI,
coherent stable files and established allocation, stack, libc and OS service
interfaces. Physical resource exhaustion is separate. We do not introduce a
libc/loader-internals audit, binary-attestation requirement, arbitrary RAM cap
or modified GCC/GNATprove toolchain. External failure remains failure, never
successful compilation or a reason to redefine membership.

Nested predecessor `open_joins` and false whole-native fields are historical
component scope. The current coverage table and conjunction explicitly
discharge their native joins; they do not erase the remaining producer/Why3,
fixed-library proof, current-grammar and final whole-rule comparison/review
requirements of #119. Production parent/compiler implementation, Bronze and
Silver verification, Lean source correspondence and admission/specification
changes remain in the already authorized later production packages.
