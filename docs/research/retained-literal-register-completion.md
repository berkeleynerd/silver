## Corrected GGC ownership and collector transfer

The sole call to `setup_prohibited_mode_move_regs` occurs at IRA entry.
Its first initialization constructs two REG nodes, one
SET and one detached INSN. Their raw upper sizes are 24, 24, 24 and 72 bytes;
each is at most 128 bytes after collector rounding. The aggregate row uses
four requests, raw maximum 72 and rounded maximum 128. It deliberately does
not substitute a summed byte budget for individual allocation checks.

The row is named `IRA_cold_prohibited_mode_probe`. All 50 prior owner rows
remain byte-for-byte unchanged; no old subtotal becomes a new row. These
detached nodes do not increment the Main instruction UID, pseudo-number or
chain counters and create no scalar or array finalizer. The early fixed
first-RTL setup owner and the Main operation/chain owners do not contain them.

For actual old event envelope E, the current collector input is E+4. Recompute:

```
active pages <= E+4
pointer-vector capacity = next_power_of_two(max(128, E+4))
each pointer-vector request = 8 * capacity
```

The signed page index, unsigned capacity and individual pointer request
checks use those corrected values. The per-request order-region check also
includes the new row. All other collector, scalar/array-finalizer, quire,
page-table and callback owners are preserved. There is no aggregate RAM
gate, scheduling-counter no-wrap claim or assumed collection count.

The earlier source/results are retained inside `predecessor_result` as
history. Their old GGC total and complete-partition claim are explicitly
superseded by the current `selected_native_GGC_ledger` and current condition
maps. In particular, the prior 47,054-event Hello record is history; the
current count is 47,058. This correction must be carried into every later
whole-native verdict rather than merely appended as an informational note.
