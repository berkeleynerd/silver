within [#119](https://github.com/berkeleynerd/silver/issues/119), Linux x86-64.
The [callable packet](../evidence/retained-literal-native-materialization-20261019/README.md)

[accepted literal invocation graph](retained-literal-invocation-join.md).
It derives capacities from that graph and the supplied actual source bytes.
There is no assumed arbitrary external materializer and no unexplained
Silver-owned parent state.

This closes the selected **parent design** obligation. It does not assert that
the current Silver driver implements the algorithm, or prove a hypothetical
implementation by checking Python. The required SPARK implementation,
Bronze/Silver verification and Lean source correspondence belong to
[#89](https://github.com/berkeleynerd/silver/issues/89). The
[Oracle](../../oracle.md) applies to every Silver-owned wrapper and remains
unchanged. Child compiler, assembler, binder and linker capacity conditions
remain conjuncts of the complete native result; this parent record supplies
none of their missing internal storage arguments. Producer/proof routing and
whole-language capacity remain outside this increment.

## Bounded copying and successful-byte correspondence

For each file, use one 4,096-byte array and these scalar ranges:

| Field | Range or meaning |
| --- | --- |
| `Length`, `Remaining` | 0 through 2^63−1; remaining bytes not yet written |
| `Loaded`, `Cursor`, `Pending`, `Request` | 0 through 4,096 |
| Source constant offset | `Length - Remaining`, used only with Pending = 0 |
| File ordinal | 0 through 12, with 12 the finished sentinel |
| Directory ordinal | 0 through 6, with 6 the finished sentinel |

Initialize Remaining = Length and the four buffer fields to zero. With no
pending bytes and Remaining > 0, request `min(4096, Remaining)` source bytes.
Check the signed `read` result before conversion: EINTR leaves all fields
unchanged; other errors fail; zero is premature EOF; a positive result must be
at most Request. Set Loaded = Pending = result and Cursor = 0. The source
bytes occupy Buffer[0 .. Loaded−1]. For constants the same operation copies
the corresponding slice; it has no external short-read possibility.

With Pending > 0, pass exactly Buffer[Cursor .. Loaded−1] to `write`. Check
the signed result first. EINTR preserves the state; any other error or zero
write fails. For `0 < n <= Pending`, set Remaining := Remaining−n,
Pending := Pending−n and Cursor := Cursor+n. When Pending becomes zero, reset
Loaded and Cursor to zero before the next read. No cumulative allocation,
retry, transferred-byte or whole-build-byte counter is maintained.

The invariant is

```text
0 <= Remaining <= Length <= INT64_MAX
0 <= Cursor <= Loaded <= 4096
Pending = Loaded - Cursor <= Remaining
destination bytes = source prefix of length Length - Remaining
source bytes read = Length - Remaining + Pending
buffer pending suffix = the next Pending source bytes
```

The last three lines are proof quantities; the implementation need not store
them. Initially they hold. A bounded read extends only the source prefix and
fills exactly the next buffer suffix. A successful partial write copies a
prefix of that suffix, decreases Remaining by n and preserves its rest.
Since Cursor+n <= Loaded and n <= Pending <= Remaining, every actual addition,
subtraction, index and conversion stays in its declared range, including
Length = INT64_MAX. The sums in the proof do not introduce a production
overflowing total. File offsets remain between zero and Length under the
regular-file I/O contract. Once Remaining is zero, probe one byte: zero
confirms exact EOF; a byte or error fails. Constant arrays establish EOF from
their exact extent. No extra byte is written to the destination.

Every positive write decreases Remaining. A read changes the finite phase
from ready-to-read to pending-write without changing Remaining. Thus
`(Remaining, phase)` is a decreasing lexicographic variant on progressing
operations, using read phase 1 and write phase 0; EOF then finishes. Interrupted
calls allocate nothing and add no counter. Eventual OS progress, or an error
outcome, is an explicit external service premise; infinite EINTR cannot be
turned into a false success or an overflow. The same argument covers empty
input, 4,096-byte boundaries, arbitrary positive partial reads/writes and
the maximum signed file extent. It is a universal arithmetic/prefix argument;
the reduced-state and byte tests exercise it without replacing it.

Open each destination with exclusive creation, write-only access and mode
0600; its directory is owned and initially empty. There are at most two
parent-owned file handles beyond the inherited standard descriptors: the
stable Main input and the current destination. Configuration constants need
no input handle. Close the Main handle after its copy and close each output
before any native launch. A close failure makes the stage fail. On this Linux
interface an interrupted close is not retried on a possibly reused descriptor.
Source handles, returned descriptors and errno use signed C-int storage; test
`-1` before using a descriptor or narrowing any interface result.

For the three fixed Silver sources, set mtime to UTC `20261018061955`,
1,792,304,395 seconds since the epoch, with nanoseconds zero. Use two fixed
`timespec` records, then verify the exact timestamp and file extent with
`fstat` while the destination handle is still open. A filesystem unable to
retain the selected timestamp fails configuration materialization. This is
the exact D-row metadata used by the accepted ALI closure, not the newer
timestamp of an arbitrary source checkout. Main and generated children retain
the coherent timestamps created on their actual producer edges. Fixed ALIs
and objects retain their exact bytes; no fixture Main ALI/object or fixture
binder source/object is initially copied.

## Sequential process routing and external outcomes

After successful materialization, form direct C vectors for each job from the
accepted strings. Append every argument with its terminating NUL; allocate
one final null pointer. Environment entries are exactly `key=value` plus NUL,
also with a terminating null pointer. No shell, interpolation, command-string
splitting, response file or inherited environment merge is used. `$ORIGIN`
therefore reaches the linker as literal bytes. The executable path is absolute;
the parent does not search PATH.

For each of the four rows, rebuild the fixed pointer vectors into its already
filled stable byte arenas, then `fork`. The single-threaded child closes no
newly shared materialization handles (they are already closed), calls `chdir`
with the row's cwd, then `execve` with its executable, argv and environment.
Failed chdir exits with status 126; failed exec exits with 127 using `_exit`.
The child branch performs no unbounded allocation, diagnostic formatting or
callback into the compiler. These syscall imports and the SPARK code handling
their results are subject to #89 implementation verification; importing an
existing libc/OS routine does not exempt Silver-owned surrounding code.

The parent stores one positive signed-32-bit PID, waits for that exact PID
with options zero and retains one signed-32-bit status. EINTR reuses the same
fields without a retry counter. On Linux, successful normal exit zero gives
status zero. Any other status is failure; no decoding arithmetic or status
accumulation is needed. Advance Job_Index only after status zero: its range
is 0..4 and the guarded final increment reaches 4. No fifth job is possible.
Fork failure or non-EINTR wait error is terminal; a wait error preserves the
one outstanding PID as an unresolved external outcome and launches nothing
else. This path never reports a completed build. No process queue or
unbounded retry/fallback branch exists.

The inherited descriptors 0, 1 and 2 remain ordinary valid standard handles.
Output and diagnostics go directly to them. The parent creates no pipe,
String, line collection, log file or byte counter for child diagnostics.
Each child receives the accepted successful-tool interface and its separately
established capacity conditions. Its own internal subprocesses are covered by
that child's source argument, not counted as additional parent launch rows.

| Parent job | Actual generated edge consumed by the following job |
| --- | --- |
| Main compile | `obj/main~1.ali` for binding; `obj/main~1.o` for linking |
| Binder generation | `obj/b__main~1.adb/.ads` for compilation; actual object-list output remains in its specified temporary role |
| Binder compile | `obj/b__main~1.o` for linking; its additional ALI remains a child output |
| Link | `root/bin/main`, with the two generated and two fixed objects in accepted order |

The parent never substitutes or parses the generated Main ALI, binder source,
binder ALI/object, or linker output. The accepted ALI writer/binder checksum
transfer and successful child contracts bind these edges. Fixed installed
library lookup and the fresh local-directory inventory remain those of the
accepted invocation join. There is no GPRbuild, Gprbind, dependency-recompile,
fixed-Silver compilation, LTO worker or fallback route in this selected graph.

Partial files and unsuccessful workspaces may remain for diagnosis after a
failure. The bounded parent closes its remaining owned handles and reports
failure; no recursive cleanup or directory traversal is needed to establish
this successful-build contract. It never labels a partial executable as a
completed effect. Permission, disk, RAM, stack, process, descriptor and I/O
failures remain documented external outcomes, distinct from decidable source
membership and from missing proof obligations.

## Representation and ABI derivation

The selected paths retain the accepted 109-byte root, 113-byte object cwd,
127-byte binder source names, 48-byte TMPDIR and P = 512 including NUL.
There are 28 distinct parent paths: six directories, twelve initial files,
eight generated outputs and two executable paths. A fixed 32 × 512-byte path
array suffices. The sixteen original pointer slots in an older GCC driver are
irrelevant to this parent's own vectors.

Each job has at most 17 argv entries and seven environment entries. Deriving
the bytes afresh from the accepted four rows gives maxima of **1,493 argv
bytes and 563 environment bytes**, including every NUL. Reserve 2,048 and
1,024 bytes per job. Eighteen argv pointers and eight environment pointers,
including their null sentinels, need 208 bytes on LP64 and may be reused only
after the previous child has completed. Offsets and lengths are unsigned
16-bit fields; all lie below 65,536. The appender checks available space
before adding. No sum of L with 18,998 or with any generated-file size is
stored or required to fit a single counter.

Even the reserved argv/environment arenas, 208 pointer bytes and a duplicate
512-byte executable spelling total only 3,792 bytes, below the 4,096-byte
POSIX minimum aggregate argument capacity and the selected Linux limit.
Individual strings are below the Linux per-string limit. Parent path
components are checked against NAME_MAX = 255, and the complete 512-byte
paths are below Linux PATH_MAX = 4096. This accounts for deterministic OS
argument/path representation limits separately from external allocation or
access failures; neither a successful launch nor a post-failure truncation
decides these bounds.

The callable gives this explicit representation layout, allowing all four
byte-vector pairs to remain resident:

| Fixed representation field | Bytes |
| --- | ---: |
| 32 path slots of 512 bytes | 16,384 |
| Eleven initial payloads | 18,998 |
| Four argv/environment arena pairs | 12,288 |
| Copy buffer | 4,096 |
| Reused argv/environment pointers | 208 |
| 32 path lengths and four sets of 17 + 7 vector offsets, U16 | 256 |
| Twelve 32-byte file descriptors | 384 |
| Four 16-byte job descriptors | 64 |
| Six directory path indexes, U8 | 6 |
| Copy/routing/scalar record | 128 |
| Fixed Linux stat storage and two timespec records | 288 |
| Payload total | 53,100 |

A file descriptor record stores its 64-bit length and timestamp, U16 path
index and payload offset, a source-kind tag and timestamp-present flag; its
remaining bytes are reserved. A job descriptor stores its U8 argument and
environment counts, U16 cwd/executable path indexes, and reserved bytes.
The 128-byte scalar record holds Length/Remaining, one signed I/O return,
the four U16 buffer fields, two descriptor handles, PID/status/errno,
file/job/directory/vector/path/append ordinals and bounded enum flags.
Each scalar has the ranges above; no hidden dynamic sequence is represented
by the reserved space. Conversion of a signed `ssize_t` result to an unsigned
`size_t` or buffer index occurs only after checking 0..4096; `off_t` and
`time_t` are signed 64-bit, `int`/`pid_t` signed
32-bit, and pointers 64-bit on the selected Linux x86-64 ABI. The ABI binding
must validate `struct stat` fits the 256-byte reserved area and each timespec
16 bytes, with alignment at most eight; the selected stat layout is 144 bytes.

All arrays are constrained and all descriptor layouts have the stated fixed
strides. Fewer than 256 scalar/aggregate field placements, each with alignment
at most eight, require less than 2,048 additional padding bytes. Thus this
explicit State representation fits a 65,536-byte reserved object. #89 must
realize and verify the declared representation, static bounds, pointer
lifetimes and ABI bindings. Fixed code/literal templates, bounded call frames
and external libc/kernel implementation storage are distinct from this State
object; this is neither a measured RSS claim nor a physical-RAM admission
limit. The configuration appender traverses only the finite 12 file, six
directory, four job, 17 argument and seven environment slots, using this
State's byte arenas. Its byte templates are the fixed selected literals and
paths, not author-controlled grammar or an additional dynamic representation.

## Closure and mandatory production work

Under the accepted immutable source/configuration, coherent filesystem and
selected Linux ABI/service premises, the algorithm has no source-length
dependent parent collection, unbounded numeric counter or missing generated
input edge. The predicate accepts precisely the recognized source/selected
graph attachment with the stated representation guards; arbitrary raw bytes
or tool success do not determine membership. Its `parent_design_residuals`
list is empty. The complete native aggregate must still conjoin every child
capacity predicate and source/emission interface using the same inputs.

Before adoption, #89 must implement all described operations in SPARK,
establish Bronze and Silver obligations automatically, and prove Lean
correspondence to the actual authoritative implementation and same-source
input flow. In particular that includes bounded template construction,
partial-I/O prefix preservation, no-overflow/termination under the explicit
service assumptions, timestamp and fixed-bundle correspondence, direct
argv/environment construction, syscall/result conversions, child ordering,
error propagation and successful-effect meaning. It must validate the ABI
representations and keep all selected invocation/child interfaces aligned.
These are mandatory implementation obligations, not an exemption for a
Silver-owned wrapper and not new design unknowns hidden in an external premise.

The packet's offline replay checks source variants, corrupt configurations,
byte-exact partial copying, boundary arithmetic, process ordering and failure
states. It reuses successful predecessor source/input evidence and executes
no compiler, binder, assembler, linker, prover, Lean build, broad replay or
native capture. The current launcher, admission and Oracle are unchanged.
