# Binder serialization: retained-family consumer inventory

2026-10-20 UTC, Linux x86_64, research [#119](https://github.com/berkeleynerd/silver/issues/119)
and [#150](https://github.com/berkeleynerd/silver/issues/150), L4. This inventory
supplies the missing writer/consumer argument for the
[selected four-job literal invocation](retained-literal-invocation-join.md).
It changes no admitted language, native option, trusted boundary or accepted
binder capacity derivation. Independent review of this increment is pending.

The binder object interface is a **retained-family transfer**. The invocation
callable takes the retained interface and the completion callable compares its
values with expected constants. That comparison checks interface agreement;
it does not inspect a binder generated from the evaluated Main. Likewise,
`binder_source_from_ali` is a conditional witness that is available to a caller,
not a check invoked by ordinary `build`. The statements describing an “actual
binder family” check must be read with this correction. Existing pinned records
and their historical results remain unchanged.

Under the retained recognizer, compiler/configuration, fixed-closure and
source-correspondence premises, the generated binder's semantic source varies
only in Main's eight-hex-digit U version. Source-path comments retain their
separate accepted renaming/width transfer. This extends the written invariance
argument to the P parameters, restriction records and U flags; it does not
derive another compiler allocation bound or run a binder.

## Restriction merge and secondary-stack state

`Gen_Restrictions` serializes all five arrays: Set, Value, Violated, Count and
Unknown. It also has callers/branches controlling exception pragmas,
finalization, multiple elaboration and the standard-allocator elaboration hook.
Therefore merely preserving Main's U version is insufficient.

The retained [fixed-ALI projection](../evidence/retained-binder-family-consumer-inventory-20261020/fixed-ali-projection.json)
shows 30 distinct boolean RV flags already present in the closure, including
No_Dynamic_Sized_Objects, No_Implementation_Pragmas, No_Implicit_Conditionals,
No_Implicit_Loops, No_Secondary_Stack and the exception/finalization flags.
`ali:2259–2273` merges boolean violations by setting True. A repeated Main
violation cannot change those entries. The indexed historical Main and the
literal Main need not have identical RV lines: the former's dynamic-size
violation is already supplied by the fixed libraries.

The [restriction partition](../evidence/retained-binder-family-consumer-inventory-20261020/restriction-partition.json)
covers all 100 real enum members (the 101st enum value is the sentinel). It
distinguishes these absorbed booleans from excluded or unchanged features.
The remaining features require tasking, protected/select/entry constructs,
access/allocator/tagged/controlled declarations, streams/attributes,
implementation identifiers/units, or different directives/configuration.
None is introduced by the recognized shell or its accepted literal lowering.
The special wide-character case is checked below. All restriction settings
remain fixed; no restriction/aspect/attribute parameter is introduced.
Checked parameter violations concern task/protected/select/entry quantities,
not the number of output calls or literal bytes. Main contributes none.
Consequently the reader's max/add/unknown rules cannot acquire a C/N/W-dependent
parameter contribution. The fixed ALIs have no parameter RR/RV values.

The P SS merge has a similar fixed witness: `closure/a-chahan.ali` contains
`P SS ZX`. It is outside the four filenames exempted by `ali:2095–2109`.
Thus `Sec_Stack_Used` is already True. No fixed task-stack row contributes an
additional count, and Main adds no task, so `Gen_Output_File` retains its
one-stack pool. This argument does not require every possible Main SS token to
be byte-identical.

## ASCII bracket encoding

The recognizer permits literal contents `[ !#-~]` or doubled quotes. In
`scng.Slit`, an interior double quote is consumed as a doubled delimiter
(`scng:1108–1127`). `Start_Of_Wide_Character` requires the three-character
prefix `[` then `"` then an identifier character (`:1276–1280`). At a bracket
inside an admitted literal, a following quote is either doubled, making the
third character another quote, or terminates the literal, making the next
non-whitespace token the closing parenthesis. Neither is an identifier
character. ESC and upper-half byte paths are excluded by the ASCII alphabet.
Literal punctuation therefore cannot introduce a hidden wide character,
different semantic token, or No_Wide_Characters contribution. Comments and
literal text do not become source names or directives.
