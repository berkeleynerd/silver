# Reporting guards with source-derived path providers

2026-10-23 UTC, #119 / #153. **Candidate, pending independent review.**
This replaces R68's hypothetical pathname orientation with a computable
interface over the actual canonical result-directory byte length R. It joins
the [pathname source argument](retained-why-report-path-inputs.md),
[noncore construction](retained-why-report-construction.md) and the accepted
[reporting composition](retained-why-reporting-composition.md). It selects no

## Explicit warning-interface refinement

R68 used a filename bound of 166 bytes and a per-warning bound of 422 bytes. Its initial/source-origin argument
alone does not establish that every later lookup preserves that filename
association after interrupted FileTags updates. The new path theorem bounds
**every stored filename origin** by 180 bytes, including the longer initial driver
names. A failed lookup or alias may select another bounded string; it cannot
manufacture a longer one. This avoids adding a new successful-publication,
no-wrap or table-persistence premise to the reporting theorem. FileTags
representation/counter safety remains a separate required owner.

Use the same accepted warning opportunity count W_o, but replace its byte
export by `L_o_new=436*W_o`. The extra 14 bytes per entry are explicitly
charged; the old R68 packet remains history under its stated scope. The new
located-warning construction ceiling is 436 bytes, still within its private 512-byte Buffer.
Other private Loc-warning construction retains its 1024-byte envelope and its
own large-margin proof. No warning is omitted or disabled to obtain the guard.

If b0/e0 are R68's standard-root affine constants (already containing the
once-per-process stderr fragment and two total exit flushes), the corrected
constants are

```
b1 = b0 + 6*(436-422)*W_o
e1 = e0 + 2*(436-422)*W_o.
```

Canonical parser warnings, final debug-buffer copies and terminal payloads
retain their existing separate coefficients. Do not multiply the stderr
fragment by drivers or renew the global exceptional allowance.

## Path and terminal substitution

The pathname theorem explicitly refines the earlier stronger any-path P to
`P_diag`, covering every dynamic pathname use in the terminal leaf/outer
rendering proof. Failed nonraising stat candidates have a separate raw-path
owner; they are not silently hidden inside this reporting result. For the
five retained clients, the conservative all-prefix request constants F are
775 / 802 / 841 / 853 / 829. These bounds tolerate interrupted filename-table
publication rather than depending on a stable source-name association.

For the actual otherwise valid canonical-directory configuration, let R be
its byte length. The intact canonical response interface then gives

```
P_diag = max(F,R+24)
M = R+72
S = max(467,F+51,R+95)
K = 723+12*S
Y = 21*(8*K+65536)
x_abort = Y+1024
X = 2*x_abort = 4032*S+2997488
B = b1+6*X
E = e1+2*X.
```

This is a source/configuration function; a particular R has not been invented
or measured here. The source families, current J12 registration, native/service
relations and future proxy/publication refinement remain required. M is a
bound on an intact selected response line, not an arbitrary socket stream.

## Decidable sufficient guards and an envelope

Evaluate the original standard-core guards without native arithmetic overflow:

```
L=B+E; I=3*E+2; T=1000000010+L+1
L+79 <= 1000000010
(3*E+1)*T+L+79 <= 2^62-1
4*I+2 <= 2^62-1.
```

Also retain the scalar terminal's private-owner guards with `E_private=2256`,
its Buffer/string rounding, the independently bounded noncore construction,
and the standard channel entry/service assumptions. The selected aggregate
stdout/stderr offer is `B+70*(E+2)+2*Y+371`. Its zero-initial-offset sufficient
test uses `<=2^63-1`; a pipe's different initial offset is not silently assumed.
This says nothing about logging-channel or raw solver-file storage.

All these expressions are nondecreasing in nonnegative R: max, positive affine
terms and products of nonnegative nondecreasing terms preserve that order.
Consequently endpoint checks can establish the guards over an interval; sample
execution is not the argument. From the first guard define

```
S_limit = floor((1000000010-(b1+e1+79)-8*2997488)/(8*4032)).
```

If `max(467,F+51)>S_limit`, this sufficient region is empty. Otherwise
`R_limit=S_limit-95` is its exact nonnegative upper endpoint, subject to the
other guards. Check those guards at R_limit. The packet also checks that the
first guard fails at R_limit+1, without claiming actual overflow there.
The resulting domain is derived from source/accounting and actual configuration
bytes; it is not an arbitrary cap adopted for Silver programs.

For these five inputs the first guard is the strongest of this set. Its
per-client R endpoints are 2264 / 5273 / 8731 / 24388 / 22329; the common
sufficient envelope is R<=2264. This envelope concerns only these reporting
owners and configurations. Normal path syntax, permissions, successful file
services, raw-path capacity and the broader toolchain rule are distinct.
At the purely illustrative `R=64` point, the smallest sentinel margin is 49,457,733.
Neither `R=64` nor `R=2264` is a selected deployment directory.
