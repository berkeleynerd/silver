# Selected literal frontend logical and physical storage join

2026-10-18, Linux x86_64, [#119](https://github.com/berkeleynerd/silver/issues/119).
This component joins the actual selected literal Main source to the accepted
fixed/configuration/frontend transfers and their individual backing predicates.
It also exports the corrected indexed physical/virtual source population for
subsequent filename and location composition. It does not establish complete
frontend, native, proof-producer or toolchain capacity. The Oracle, tool pins,
current language, and admission remain unchanged.

The [computable leaf](../evidence/retained-literal-frontend-storage-20261018/compose.py)
accepts the same source bytes and
[selected route descriptor](../evidence/retained-literal-pipeline-20261018/selected-route.json)
as the existing aggregate. Its source family remains the complete
[literal-shell recognizer](retained-literal-native-frontend.md): one
`with Silver_IO;`, Main/SPARK shell, direct qualified literal Put/Put_Line calls
and nulls, with at least one call. It does not enlarge that source family or
promote the current complete-source cap to an unbounded tool theorem.
The source argument below composes accepted source transfers; the focused
examples exercise their implementation and arithmetic.

## Actual source and invocation binding

`bind_descriptor` reads the selected descriptor and its core descriptor,
checks P=512 spelling bytes and 4096-byte pages, and constructs the accepted
[native invocation](retained-literal-invocation-join.md) using P+1=513 bytes
including NUL. It requires all native/datarep/phase1/phase2 Main paths to equal
the graph's authoritative Main path. It joins the complete source recognizer's
counts and source hash to that invocation and the numeric component.

The configuration is the actual 327-byte indexed naming input; the source
map is the graph's exact four unit/basename/path triples for Main,
silver_io.ads, silver_io.adb and silver_output_libc.ads. Shared source and
System bytes must equal the invocation's checked materialization identities.
The native switches remain `-gnatx`, `-Wno-free-nonheap-object` and
`-fsplit-wide-types`; the current gnat1 argv allowance is 25 positions.
No 24-position null command-storage result is substituted. The leaf does not
price command storage or the complete ALI serializer.

The fixed Silver source/object/ALI bundle remains configuration input on this
route. Only Main and the generated binder are compile jobs. The earlier
invocation packet supplies fixed object/ALI correspondence, environment,
ordered search, absent default path files, timestamps and path premises.
This leaf reads its source inputs and computes the Main child projections; it
does not materialize directories or execute those jobs. Stability of the
checked files through their future use and the actual launcher implementation
remain interface premises.

## Logical table join and backing

The leaf calls unchanged `native_frontend_logical_join` with the actual
`Main_counts`, all six scanner pools, actual maximum word length, no input
identifier correction, zero loop depth, P=512, actual map/configuration
storage, and the accepted indexed configuration delta. It checks exact equality
of the resulting Main constructor vector with the source adapter's vector.

The predecessor's fixed witness is deliberately retained in full. It includes
the captured fixed lifetime, 288 implicit-with ordinary nodes, all first-lookup
element-list residues and the two default naming pragmas. The indexed naming
line adds 18 ordinary nodes, 162 slots, two lists, two String descriptors,
16 String characters and its scanner/helper names. Thus the fixed node
allowance is 41,234. The Main vector is not added twice merely because parser
nodes also account for scanner-produced identities. Scanner name/String pools
remain separate from their parser-node allowances.

The existing common metadata and invocation transfers add qualification,
overload, unit-boundary element lists, signature names, invocation constructs,
relations, targets and scenario storage. They retain their actual container
distinctions. `native_configuration_storage` charges each actual map record,
its names, file/path mapping tables, search-directory tables, individual map
read buffers, hash wrappers and buckets. Empty path-file lists mean the
selected invocation's absent `ada_source_path`/`ada_object_path` inputs; they
do not mean arbitrary path files have zero cost.

`native_core_table_backing`, `native_parser_auxiliary_backing` and
`native_invocation_backing` then run unchanged, at the selected default
Table_Factor=1. The table envelope retains initial backing, growth products,
logical nominal index domains, sentinel positions and individual allocation
sizes. Source-derived record-size upper bounds, hash nodes/buckets, iterator
counters and parser auxiliary records remain those of the accepted
[native expansion argument](retained-native-expansion.md#core-native-table-backing-and-caller-checks).
Relocation overlap subtotals are descriptive; they are not aggregate RAM
admission gates. Native allocation success remains an environmental premise.

`-gnatx` gives zero appended Xrefs entries under the accepted selected no-xref
argument. The common semantic transfer remains present and initialized table
and hash backing remain charged. No semantic reference marking or required
proof obligation is suppressed by this capacity calculation.

## Numeric projection without duplicate fixed charges

The [numeric leaf](retained-literal-ada-numeric.md) supplies the same actual
source's fixed, scanner, Main, fixed floating callback and original-gigi callback
rows. The frontend verifies that its three pre-callback numeric projections
equal exactly the first three numeric rows. It then **replaces** the Uint,
Udigit and Ureal table demands with the accepted lifetime demands. It does not
add the complete numeric fixed/Main sum to an already counted frontend sum.
Rep_Table stays in the numeric component and has no second core-table charge.

For C calls, let k=uint_digits(C+2), with the pinned base-32768 digit count.
The Main output-wrapper scope value can require more than one word, so the
general numerical demands are:

```text
Main Uint appends          = 7C
Main retained digit words  = C(60+k)
lifetime Uint entries      = 28,420 + 9C
lifetime retained digits   = 107,726 + C(70+k)
lifetime Ureal entries     = 67
lifetime Rep_Table entries = 504.
```

The earlier simplification 61C Main words / 107,726+71C lifetime words applies
only when C+2<32768. The boundary C=32766 must use k=2. The retained component
uses the actual Main vector rather than narrowing the source family to
preserve that simplification. The accepted numeric packet also checks its
local Uint/vector objects and callback argument coverage separately from the
lifetime table growth.

The numeric implementation dependency is correction `64237926eb` (locally
cherry-picked as `3531a5e2e3`); the original fixed/callback transfers are
retained. Independent review report `b6669b3ff7` accepted that correction and
the selected-route numeric attachment separately. Its frontend finding is
addressed below; the corrected frontend packet awaits the narrow addendum
before aggregate adoption. No earlier review is represented as a review of
these corrected frontend inputs.

## Whole runtime union, line objects and virtual sources

The accepted
[indexed physical-load correction](retained-native-expansion.md#indexed-native-main-physical-source-load-correction)
is essential. The original 38-specification semantic inventory alone does not
replace it. Under the selected basename-to-source mapping and search controls,
successful imported nonindexed unit loads persist and do not accumulate
another buffer for the same requested Fname. The startup System load precedes
that unit record; allow one additional System physical buffer for indexed Main.
The six source-load call sites and their exclusions remain those of the
accepted correction. This is a request-name argument, not an inode argument.
Changed aliases, naming or search controls require a new join.

The leaf rechecks the complete installed runtime file-set digest, all 1,575
file identities and their aligned sum 20,496,384. The extra System input is
7,503 bytes with q=8,192, making the corrected runtime physical allowance
20,504,576. For q(B)=4096 ceil((B+1)/4096), the joined source extent is:

```text
q(Main) + 20,504,576
        + q(silver_io.ads) + q(silver_output_libc.ads)
        + q(actual 327-byte configuration)
        + 7 q(Unchecked_Conversion spec)
        + q(Image_I spec) + q(Image_I body).
```

The selected Silver specifications contribute 8,192. Both are materialized
inputs; charging the second spec even if Main does not load it is conservative.
The materialized silver_io.adb body is not a Main source-load job on the
selected no-inline route. The possible physical Image_I body is already in
the runtime union. Its possible virtual copy is a separate charge.

The seven Unchecked_Conversion copies and Image_I specification/body copies
give nine virtual entries and 40,960 virtual positions. This retains the
accepted full-root source overcount; no direct literal call instantiates a
new generic, loads a user body, or adds an inherited/inline virtual copy.
The constructor/type frontier and the existing body/inline/inherited-contract
exclusions supply that fact; an observation from a null process does not.
`Create_Instantiation_Source` (`sinput-l.adb:127–165`) copies the template's
source record and shares its text/line arrays, so virtual extents do not
allocate another physical text or line-table object.
Each virtual copy nevertheless allocates a `Dope_Rec` for its adjusted source
bounds (`sinput-l.adb:245–252`, type at `sinput.ads:892–898`). The leaf exports
up to nine such metadata objects and explicitly leaves their individual
storage outside this projection. Sharing the text/line arrays does not cover
that metadata allocation.

Each physical source is separately priced. `source_object` counts CRLF once,
lone CR/LF once, expands tabs from one-based columns, and computes the line
capacity starting at 500 and doubling until it covers the line-entry bound.
It checks B+1 in Int, B+17 as the individual source allocation upper bound,
32*capacity in Int before byte-size conversion, the line successor, and final
expanded column <=32766. These follow `sinput.adb:98–175`,
`sinput-l.adb:488–542` and the existing scanner column argument.

The full pinned runtime contains no VT/FF and no executable Source_Reference
pragma, as checked by the runtime scan. The selected configuration and Silver
inputs also satisfy those checks; Main's recognizer excludes those constructs.
The two logical-line allocation branches therefore remain absent
(`sinput.adb:130–175`). The retained runtime maxima are a 784,306-byte individual
source-buffer upper bound, a 64,000-byte individual line array, 12,565 line
entries and expanded final column 172. These maxima describe separate objects,
not one combined allocation. Main and the extra fixed inputs have their own
source/line rows. GCC line maps and combined locations remain a later join.

The extent minus one must be <=Int'Last-4096, preserving the final source-block
increment. This also covers the static Source_File_Index_Table's indexed
coordinate access; its fixed individual size uses 2+floor(Int'Last/4096)
four-byte entries (`sinput.adb:72–87,851–864`).

## Permanent source entries and the indexed filename dependency

The corrected source population is explicit:

| Contribution | Upper bound |
| --- | ---: |
| Entire installed runtime physical union | 1575 |
| Additional indexed System physical buffer | 1 |
| Selected Silver specifications | 2 |
| Main and actual configuration | 2 |
| Physical total | 1580 |
| Fixed virtual copies, including possible Image_I body | 9 |
| Permanent Source_File entries | 1589 |
| Failed-load transient slot for Source_File backing only | 1 |

Failed physical loads decrement Last before returning (`sinput-l.adb:420–430`),
so their one spare slot belongs to table backing, not the backend's successful
source loop. Source_File demand is 1590, at 464 bytes per record, using the
accepted 29-field/16-byte-per-field upper bound. Instances has demand ten,
including its sentinel. SFN_Patterns uses the fixed four plus two default
patterns, giving six; SFN_Table uses the one indexed Main entry. Each table
uses its actual low/initial/growth parameters. The indexed SFN hash has an
individual 808-byte bucket array and one 16-byte wrapper. The six Strings
allocated by configuration are an additive delta, rather than the lifetime
count. `Fname.UF.Initialize` runs at package elaboration (`fname-uf.adb:659`)
and at frontend initialization (`frontend.adb:88`); each call allocates four
Strings for the two default pattern/dot pairs (`fname-uf.adb:444–453`).
`Table.Init` resets the table and may reuse its backing; it does not free the
String pointees (`table.adb:128–154`). The two configuration pattern pragmas
each allocate a pattern String, a default dot String, then the explicit
replacement dot String (`par-prag.adb:674,713,848,869`). Thus the lifetime
allowance is **8 default + 6 configuration = 14 String objects**, each
individually bounded by 5+16=21 bytes. The indexed Main naming entry adds no
pattern String. `pattern_String_allocation_rows` preserves the lifetime and
configuration-delta projections separately.

`back_end.adb:80–130,172` sends every permanent source entry, including virtual
copies, through a three-four-byte-field File_Info record. Its array has at
most 1589 entries, bounded by 19,084 bytes including a conservative descriptor.
`trans.cc:282–363` performs at most 1589 filename lookups, and
`utils.cc:877–885` adds the translation-unit filename lookup. Thus export
1590 insertion-capable filename lookups and the existing shared-identifier
transfer's conservative 3180 direct calls. The source table's failed-load
slot is not an additional filename lookup.

This corrects the earlier original-shared packet's 1588 permanent entries /
1589 filename lookups, which omitted the startup-System duplicate. Its
success is retained as historical evidence. A later shared identifier,
filename, source-location and combined-location join must propagate these
corrected numbers and recalculate its incoming/history/serial/hash bounds;
this packet does not edit that accepted source argument or assert that such
later backing is already priced.

## Gigi array and selected frontend name inputs

For the actual joined frontend node upper allowance n, `back_end.adb` passes
Num_Nodes through the signed Int `max_gnat_node` argument. `utils.cc:430–439`
allocates two `ggc_cleared_vec_alloc<tree>(max_gnat_nodes)` association arrays.
The leaf therefore exports two separate raw requests of 8n bytes, checks
0<n<=Int'Last and each raw request in signed 64-bit pointer-difference range.
Allocation rounding, pages and other gigi arrays remain separate consumers;
these are not complete GGC event or byte totals.

Only the name projection of `native_source_and_frontend_name_backing` is
selected. Its older 38-spec physical inventory is not used for the physical
join above. The accepted source name argument bounds Main qualification,
fixed nonpath decimal-run normalization, selected Integer encoding and the
external-name prefix; the maximum resulting spelling must fit the 4096-byte
Bounded_String. Core table backing separately checks interned Short lengths
and the larger Name_Buffer. Arbitrary later name constructors and GCC suffixes
remain named obligations. Actual filename spellings use P=512/P+1=513 and
their later shared-pool projection.

For the retained 118-byte hello source the joined n is 41,294, each association
array raw request is 330,352 bytes, and the selected frontend encoded-name
upper bound is 737. Its physical/virtual extent is 20,561,920, with Source_Last
bound 20,561,919. These are component allowances for these exact inputs.
