2026-10-18, Linux x86-64, research [#119](https://github.com/berkeleynerd/silver/issues/119).
The [callable aggregate](../evidence/retained-literal-pipeline-20261018/README.md)

**Whole literal-pipeline capacity remains unestablished.** The bounds-pool
declaration lifecycle and shared tree/assembler-name backing now have a

have a conditional join, and the literal-sized ranger/out-of-SSA backing is

No production rule or option changed; #119 remains incomplete.

## One source counter interface

The existing complete recognizer accepts one `with Silver_IO;`, Main/SPARK
shell and a nonempty sequence of qualified literal `Put`, `Put_Line` and
`null` statements, with at least one output call. It handles doubled quotes,
empty literals, ASCII case and permitted trivia. The aggregate additionally
requires the current ASCII alphabet, excluding VT/FF. It does not enforce
today's source-byte cap or define a new admission rule.

Let C count calls, N count null statements and W be the sum of decoded literal
lengths. The scanner supplies these values to the existing native lowering,
data-emission, final RTL and helper-backing callables. Their joins check the
pre-split register extent `98+3C`, post-split extent `99+5C` and final first-unused
UID `7C+7N+46`. The proposed native-only split option is explicit; it is not
silently forwarded to the producer.

The same complete tokenization supplies Why's word count and maximum identifier
length. Its source counters are `S=X=P_output=C`, with C qualified-call/dot
occurrences, N nulls, and one context clause. Each statement supplies its own
shape region. The older illustrative lexical helper, which does not strip
comments, is unused. Distinct literal occurrences remain distinct even when
their decoded bytes agree. There are no declarations, concat results or parser
flattenings in this class, so the corrected literal-definition sum is exactly
`H_chars=W`; the existing expression-visit allowance is `V=2C`, and both
`K` and `K_literal` equal C. The aggregate checks these equalities.

One input record supplies the actual naming, System and three Silver library
files. Their bytes are checked against the retained naming/System identities
and current library inputs. Native, data-representation and both light phases
name the same Main launch role. This is a shared-input binding, **not yet a
complete output launch descriptor**: maps, search closure, options and the
additional fixed compiler/producer subprocesses still require composition.
The completed null graph is not relabeled as an output graph.

For Hello World, C=1, N=0 and W=13 give a final pseudo extent of 104,
first-unused UID 53, 53 text bytes, 35 data bytes including alignment and a
189,744,712-byte hypothetical general Why JSON bound at P=512. The reviewed
[literal producer specialization](retained-literal-producer-specialization.md)
establishes that Main emits no `.gnat-json` because it registers no Why3
checks. The aggregate uses that specialization, preserving every construction,
intern-pool, undo and String condition and checking exact source/native/Why
counter equality and equality of the general envelope. Its hypothetical JSON
bound remains diagnostic; fixed-library Why inputs and final reports still
need their capacity joins. The body/data formulas
remain conditional on their existing whole-unit Main-preservation and selected
source/option premises. The text-byte bound and instruction count alone
are not an ELF-object contract; the separately reviewed interface below
supplies that additional selected envelope.

The accepted [binder checksum closure](retained-binder-checksum-closure.md) is
also replayed once per evaluation context. Its universal 5,167,732 rounded-byte
bound remains 75,148 bytes below the 5 MiB first-collection threshold. That
component retains its own fixed binder source/options/path projection; the
aggregate does not infer a complete binder invocation from the common Main
path. Checksum variation is no longer an unresolved research obligation.

The separately reviewed [literal assembler interface](retained-literal-assembler.md)
is also attached to this aggregate. It scans exactly the same source bytes;
the join checks C/N/W/maximum-length, final RTL chain, text-byte and rodata-byte
equalities. Its `local_interface_fits` predicate contributes the complete
selected assembly-stream, alignment-region, symbol/relocation and ELF-object
envelopes. The accepted [GAS/BFD storage join](retained-literal-assembler-storage.md)
now contributes its separate `selected_GAS_BFD_storage_fits` conjunct, with
exact equality against the attached assembler interface. The descriptor's
P bounds path spelling bytes, so this storage interface receives P+1 for
the terminal NUL. Its complete selected GAS dynamic-request and output-BFD
storage closure remains conditional on the reviewed source/configuration
and invocation premises. These are source-derived capacity bounds, not an
observed object. `Main_assembler_and_object` retains the complete production
invocation/materialization join. Binder/fixed-object/final-link consumers
remain in their separate aggregate interfaces.

### Incoming shared state

The retained [fixed-prefix capture](retained-native-expansion.md#fixed-root-read-projection-and-no-collection-before-main)
stops before `Compilation_Unit_to_gnu`, after **39,257 positive GGC allocation
events**. It excludes wrap and collection and retains executable, arguments,
environment and source identities. This is historical Linux evidence, not a
new execution. The first four fixed Standard roots have the same relevant
projection in this literal shell: Natural, A_Char, the exception record and
Long_Long_Float are constructed by Cstand, retain their fixed Standard scope,
frozen state, representation and target widths, and cannot be altered by this
shell's declarations or pragmas (`cstand.adb:192–220,1015–1036,1161–1168,
1526–1587,1746–1762,1819–1848`; `freeze.adb:6536–6553`). Referencing Standard
String later does not add a root to the explicit pre-Main gigi sequence.
The optional wide-split flag changes a later RTL pass; it changes no selected
prefix constructor recipe. Native output uses the same naming-only semantic
configuration, target and no-debug settings as the prefix transfer.

Filename identifiers, source maps, the two association arrays and their shared
identifier-hash growth remain variable. Their source routes do not call
`build_constant_desc`, `tree_output_constant_def`, symbol registration or the
constant-pool insertion API (`trans.cc:293–363`; `utils.cc:430–449,878–884`).
Therefore the fixed prefix event allowance can be used conservatively for the
number of pool descriptors without pretending those metadata allocations have
fixed bytes. Each descriptor requires a distinct positive GGC allocation
(`varasm.cc:3720–3731`). No subtraction of sampled metadata is used.

Set `D_in = 39257`. Before Main's pool demands, live and occupied pool entries
are each at most D_in; deleted entries are at most occupied. The table's initial
request 1009 rounds to 1021 (`varasm.cc:6959–6963`; `hash-table.cc:43–76`).
It has no independent reserve operation. Applying its source growth rule to
this prefix bounds its incoming capacity by
`prime(max(1009, 2*D_in)) = 131071`. These are conservative upper bounds, not
measurements of pool occupancy and not an assumption that the pool is empty.

There is no uncharged post-prefix dependency body before Main. The native
`N_With_Clause` path either returns an empty list or constructs namespace
metadata (`trans.cc:8333–8339,6455–6515`). The recursive all-entities walk is
exclusive to `type_annotate_only` (`:9670–9720`), which is not this native
phase. The called Silver_IO declarations are external procedures with no
native body, initializer, alias or Inline_Always attribute. Static Ghost state
and static contracts are erased; Main does not reference the package variables

external FUNCTION_DECLs (`utils.cc:3772`; `passes.cc:176–250`). Thus the only
post-prefix tree-pool additions for this family are the previously derived
bounds/literal roots. This native projection does not cover datarep or producer
frontend translation of dependencies.

The existing [fixed symbol-ingress argument](retained-native-expansion.md#null-mains-incoming-ipa-symbol-graph)
transfers only its prefix portion: builtins register declarations, not cgraph
nodes; the three ignored external OTHERS variables and Boolean CONST_DECLs do

### Bounds declaration analysis, references and release

Each `tree_output_constant_def` finalizes the descriptor's existing VAR_DECL
(`varasm.cc:3989–3995`). At most C calls create at most C `varpool_node`s;
`get_create` preserves its existing-node guard (`varpool.cc:136–166`). Each
new node requests at most 256 GGC bytes by the already reviewed source-layout
ceiling. It is additional to the pool descriptor and VAR_DECL already charged
in the direct 10C pool-object allowance. Registration links the node, advances
UID/order, clears zero-length vectors without reserving storage and inserts
its assembler name if that table exists (`symtab.cc:412–425`,
`cgraph.h:3137–3150`, `ipa-ref.h:133–138`). The bounds declaration has null
context/file scope, so default assembler-name selection reuses its existing
LC identifier (`langhooks.cc:138–181`); there is no private-name suffix counter
or extra identifier allocation on this path.

The bounds declarations are created while Main is gimplified inside
`analyze_functions`, with symbol state `CONSTRUCTION`. `finalize_decl` sets
`definition` once. It can enqueue through the existing `aux` pointer if needed
or referred to, but neither its `state >= IPA_SSA` analysis branch nor its
`FINISHED`/`EXPANSION` assembly branch runs at this point
(`cgraphunit.cc:968–1013`). The reachable graph walk subsequently enqueues each
referenced bounds node. `aux` suppresses duplicate queue insertion within an
analysis invocation; the two outer analysis invocations give at most 2C
insertions without a heap queue (`:288–295,1176–1192,1251–1364,2593–2599`).
The outer `!vnode->analyzed` guard supplies at most one analysis per node.
This guard matters: `varpool_node::analyze` itself guards alignment, but does
**not** guard its initializer walk with `!analyzed`.

The actual initializer is one two-element CONSTRUCTOR with Integer bounds
`1` and `L`, including `L=0` for an empty literal. Its two SI fields give
8 bytes, with no address, alias, TLS, vtable or dynamic size.
`align_variable` and the x86 data/constant alignment branches inspect existing
size/mode/alignment fields and create no tree (`varasm.cc:1129–1193`;
`i386.cc:18589–18688`). `record_references_in_initializer` creates a local
`hash_set<tree>` with 13 pointer slots: **104 ordinary bytes**, one request per
analysis (`cgraphbuild.cc:408–419`; `hash-set.h:38–41`).
`walk_tree_1` visits the CONSTRUCTOR and its two values; it does not follow
constructor field indexes or implicit type pointers (`tree.cc:11719–11835`).
Equal Integer nodes reduce that count. Canonicalization returns the same
CONSTRUCTOR and INTEGER_CSTs, without folding a new expression
(`gimple-fold.cc:200–271`). Therefore at most three entries enter this hash,
no expansion occurs, and the initializer creates **zero outgoing references**,
new symbols or GGC objects (`cgraphbuild.cc:49–111`). Destruction releases the
ordinary backing.

Incoming references require a different count. Each pointer-field store of a
bounds address can create one Main-to-bounds `IPA_REF_ADDR`; the paired literal
address is a STRING_CST, not a symbol declaration. There are at most C live
references, even when equal bounds coalesce and all C refer to one node. The
selected schedule has one initial graph build and three rebuilding passes
(`passes.def:45,67,74,118`). Each rebuild removes Main's old references first
(`cgraphbuild.cc:424–460`). O0/no-offload excludes the other nested rebuilding
pass; strub/split transformations and cloning are absent for this body and its
external callees. No inlining body is available. Hence at most 4C reference
creation operations and at most 4C call-edge creation operations occur. The
latter feed the direct-call graph/summary join below.

`create_reference` grows Main's value vector and a bounds node's incoming
pointer vector, then repairs pointers if the first moves (`symtab.cc:621–665`).
Each vector has length at most C. The heap growth recipe starts at four, doubles
below 16 and otherwise multiplies by 3/2 (`vec.cc:150–170`), giving capacity
`V_ref=max(4,2C)` and a conservative `3C <= UINT_MAX` intermediate check.
Charge at most 4C requests of `8+48V_ref` bytes for Main's vector and at most
4C requests of `8+8V_ref` bytes across bounds incoming vectors. The 48-byte
ipa_ref ceiling rounds three pointers, two scalar words and three separately
charged bitfields to LP64 alignment (`ipa-ref.h:40–68`). These are ordinary
requests, not GGC events. Capacity uses the 31-bit vector field; signed
iteration and pointer-repair loops also require `C <= INT_MAX`. At most 4C²
pointer repairs bound the cumulative work without turning time into an
admission budget.

No bounds node is reclaimed and recreated between these scans. The early
inliner clears Main's references (`ipa-inline.cc:3239`), but without
always-inline bodies its O0 route makes no body change or additional scan;
the last scheduled graph rebuild restores the bounds references before
whole-unit unreachable-node removal. The queued inline transform clears the
references again after the whole-unit IPA passes
(`ipa-inline-transform.cc:809–883`); its O0/no-inline guard skips
`optimize_inline_calls`, and later releases do not rerun gimplification.
`cgraph_node::get_body` would add another rebuild when consuming queued
transforms, but its only callers are SIMD cloning and IPA PTA
(`omp-simd-clone.cc:241,642,2004`;
`gimple-ssa-pta-constraints.cc:3905`), both excluded here. Main's actual
expansion calls `get_untransformed_body` and
`execute_all_ipa_transforms(false)` (`cgraphunit.cc:1845–1869`). `get_constructor` returns the
existing initializer in this non-LTO process (`varpool.cc:275–285`). Assembly
uses the existing pool guard and emits each descriptor at most once
(`varpool.cc:568–604`; `varasm.cc:2565–2601`). The possible later
`output_constant_def` lookup of its pool VAR_DECL is already among the 3C
lookups. Alias walks are empty, late-debug hooks do nothing, and no new symbol
is constructed. Removal releases references, unlinks the assembler hash and
frees the node (`varpool.cc:171–208`; `symtab.cc:452–480,825–841`). Selected
O0 disables IPA-reference/ICF hooks, and there is no polymorphic query to
install the devirtualization hooks (`ipa-reference.cc:1304`,
`ipa-icf.cc:2310–2320`; `ipa-devirt.cc:330–350,3190–3202`).

### Shared backing and returned delta

The shared tree table has at most `D_in+2C` live or occupied entries. Its at
most 3C insertion-capable lookups can each replace backing **before a hit**.
The returned per-request ceiling is
`8*prime(max(1009,2*(D_in+2C)))` bytes and the replacement-event ceiling is 3C.
The incoming allocation remains in the retained prefix, rather than being
added a second time. The existing [hash lemma](retained-backend-capacity.md#hash-backing-and-probe-arithmetic)
requires `D_in+2C <= 1073741823`, keeping the capacity at most 2147483647 and
32-bit probe addition free of wrap. Deletion/cleanup can only reduce live
entries; tombstones are included in occupied state and pre-hit growth is paid.

The assembler-name table is initialized at most once, at or before the end
of the first analysis (`cgraphunit.cc:1447–1454`; `symtab.cc:260–268`). Charge
its 128-byte control and initial backing cold. The hard-register dummy is
excluded; at most `C+3` Main/callee/bounds symbols can be inserted, once each,
whether they precede table initialization or arrive after it. There are no
clones, aliases, renames or name reordering calls in this selected path.
Consequently the hash has at most `C+3` entries and at most `C+3` growth-triggering
lookups. Charge `C+4` initial-or-replacement requests, each at most
`8*prime(max(10,2*(C+3)))` bytes. This is deliberately conservative for small C.
The same hash lemma applies. One nontrivial hash-control destructor adds at
most one singleton-finalizer registration; it allocates no object when run.
Its shared registration-vector backing belongs in the subsequent collector
join (`ggc.h:193–201`; `ggc-page.cc:1331–1346`).

The newly joined requests therefore contribute at most **5C+5 GGC events**:
C bounds nodes, 3C tree-hash backings, one assembler-hash control and C+4
assembler-hash backings. Fixed Main/callee/dummy nodes, the forced dummy's tree
and identifier, the direct 10C pool objects, all other helpers and shared
collector backing stay in their own lifetime terms. No 40,098-event null
allowance is reused. Each request is checked separately; simultaneous memory
and physical resource availability remain external assumptions.

## Direct-call graph and IPA-summary lifetime

in the established [39-registration IPA partition](retained-backend-ipa.md)
with Main, at most two external callees, at most C bounds variables and the
forced dummy. Main remains the only defined function body. Calls are direct,
nonrecursive and have no callback, always-inline, clone, thunk or target
attribute. The variables have no outgoing initializer reference. The selected

### Edges, lookup tables and IDs

The initial graph construction and three scheduled rebuilds create at most
4C edges. `symbol_table::create_edge` always allocates a fresh GGC edge; the
comment about a free list at `free_edge` does not establish object reuse
(`cgraph.cc:1067–1140,1238–1246`). Each rebuild removes old callees first,
so at most C edges are live. The UID starts at one and preincrements, giving
endpoint `1+4C <= INT_MAX` (`cgraph.h:2560`; `cgraph.cc:1090–1092`). The edge
has a 16-byte profile count, nine pointers, two scalar words, ten bitfields
conservatively charged as separate four-byte units, and two integer IDs:
at most 144 raw bytes after LP64 alignment (`cgraph.h:2120–2222`).
No indirect-info object is allocated for these edges.

A lookup may construct Main's call-site hash after more than 100 linear
probes (`cgraph.cc:906–951`). Charge one 128-byte control and initial
prime-127 backing per graph generation even when no hash is needed. Once
created, that generation inserts each of its at most C edges once. Neither
selected local nor whole-unit work changes a call statement or creates an
additional edge. Insertion may expand before a hit, so charge C replacements
per generation and use `8*prime(max(120,2C))` bytes per backing. The existing
hash/probe lemma applies under `C <= 1073741823`.

**Terminal emptying is a separate allocation opportunity.** Both
`remove_callees` and node removal call `call_site_hash->empty()` and then set
the pointer to null (`cgraph.cc:2144–2147,2359–2363`). `release_body` delegates
to `remove_callees` (`:2229–2259`), so overlapping cleanup paths cannot empty
the same lifetime twice. `empty_slow` can allocate a replacement backing
(`hash-table.h:909–951`). Charge four such requests, in addition to the
`4+4C` initial/insertion backings. Its large-table branch requests 128 slots,
rounded to 251, only when the prior pointer table exceeds 131,072 slots;
otherwise it requests at most twice the old population. Both fit the same
per-request ceiling. The tests exercise both sides of this branch. Discarding
the control afterward does not erase the allocation event.

Call-summary IDs are distinct from edge UIDs. Freeing an edge pushes any
assigned summary ID onto an ordinary released-ID vector. Assignment reuses
that vector before increasing its high-water counter
(`cgraph.h:2782–2790`; `cgraph.cc:1238–1246`). All old edges are freed before
the next generation, so the high water is at most C, not 4C. The call-summary
pointer vector starts with capacity 13; `max(13,2C)` bounds its later ordinary
capacity. The released-ID vector has capacity at most `max(4,2C)`. Check both
31-bit vector capacities and the `3C` unsigned growth intermediate. Function
summary ID zero belongs only to Main and survives manager replacement.

### Local summaries and fixed infrastructure

There are two local summary scans and one global manager-generation entry
(`passes.def:75,119,174`). Each local scan creates at most C ordinary
32-byte call-summary records and one GGC Main function-summary record
(`ipa-fnsummary.cc:3386–3405,3042–3137`;
`ipa-fnsummary.h:276–307`). Each record's predicate pointer remains null:
`edge_set_predicate` receives true. The parameter manager is absent at both
local scans, so the presence of one call argument does not allocate the
per-argument summary vector. O0 also excludes the optimizing body-info,
nonconstant-name, condition, loop and target-info paths. Global generation
then allocates propagation infrastructure but skips Main's analysis; the two
external callees have no body (`ipa-fnsummary.cc:2856–2943,4698–4716`;
`ipa-prop.cc:5211–5218`). No insertion/duplication callback runs afterward.
Thus the parameter, edge-argument and value-range maps all remain empty.

The source-derived fixed constructor rows of the earlier
[summary infrastructure join](retained-native-expansion.md#function-summaries-and-ipa-propagation-infrastructure)
transfer structurally, without its null lifetime subtotal. Charge three cold
manager groups and two local function records: three 512-byte GGC function
managers, three 128-byte GGC vectors, two 128-byte function records, two
512-byte propagation managers, two 208-byte empty embedded-map backings, one
128-byte value-range hash control and one 488-byte empty backing. These are
**14 GGC events**. Ordinary size/call managers and growth caches fit 512 bytes;
their initial pointer vectors fit 112 bytes. The ordinary pool block request
is 65,536 bytes, with at most 2C call-record allocations and three cold
size-record blocks. The reused 37-hook allowance has 24 bytes per hook.
No edge-growth or context-cache record is created by the O0 candidate loops.

For each local scan put `S=3C+N+2` and `B=N+4`, conservative post-CFG statement and
block-slot ceilings from the existing literal GIMPLE interface. The necessary
statement worklist adds each statement at most once; virtual operands do not
enter its `SSA_OP_USE` loop. Its capacity is at most `max(4,2S)`, and the block
cache capacity is at most `max(10,2B)`
(`ipa-fnsummary.cc:2770–2849`). There is no GIMPLE_COND, so the unreachable-guard
walk is not entered. The block order request is at most `4B` bytes. Its CFG
preorder helper reserves `B+1` 16-byte edge iterators, with twenty inline
slots and no separate visited bitmap (`cfganal.cc:979–1070`;
`basic-block.h:361–364`; `vec.h:1681–1693`). The callable conservatively
returns `8+16*max(20,B+1)` even when storage is inline.

The size/time table receives two seed requests and at most two requests per
statement. GCC itself merges overflow into the first entry after 256 entries;
this is an internal algorithm bound, not a Silver admission cap
(`ipa-fnsummary.cc:167–246`; `ipa-fnsummary.h:218–220`). Thus capacity
`max(4,2*min(256,2+2S))` and a 96-byte entry ceiling cover its ordinary vector.
The separate call-size/time table is not constructed: the local scan has no
parameter manager and global O0 generation does not analyze Main
(`ipa-fnsummary.cc:3756–3762`).

The summary's signed size accumulators need their own check. An 8-byte
pointer store and a 16-byte fat-pointer argument each have move cost at most
four on the selected x86 target. ADDR_EXPR adds no operator cost; a direct
one-argument void call has size at most five. Return contributes one and the
default prologue contributes two; nulls, labels and gotos contribute zero
(`tree-inline.cc:4275–4300,4430–4434,4464–4610,4718–4742`;
`config/i386/i386.h:1917–1956`; `defaults.h:984–986`;
`params.opt:1230–1236`). No ARRAY_REF with an SSA index adds address cost.
Consequently unscaled size is at most `13C+3`; size-scale two and the final
`RDIV` rounding numerator require **`26C+7 <= INT_MAX`**
(`ipa-fnsummary.cc:3155–3241,3621–3635,4620–4646`). This covers each partial
nonnegative sum, both size/min-size accumulators and their local products.

Time costs are stored in `sreal`, not a signed integer running total. Per-call
time is at most fourteen, per-store four and return two. It is unnecessary to
assume a sampled or exact block frequency: `profile_count` stores at most
60 value bits, and `to_sreal_scale` returns zero, one, a ratio of such counts,
or four times the numerator when the denominator is zero
(`profile-count.h:771–786`; `profile-count.cc:333–363`;
`cgraph.cc:4764–4769`). This multiplication fits signed 64-bit before conversion,
and every positive ratio is between 2^-61 and 2^63 after rounding.
Initial weighted terms are below 2^68. For a deliberately loose exponent
check independent of rounding order, allow one exponent increase per positive
addition: rounding cannot exceed the next representable power of two. The
main time sum sees at most `3C+1` cost-bearing statements. Calls have separate
edge summaries; the noncall table receives at most `4C+2` cost-bearing
accounts, followed by at most 256 table reads and C edge additions. Thus
`5C+400` is a conservative exponent ceiling for either accumulation path;
the default zero prologue, multiplication by a probability at most two and
division by two are covered by its constant allowance. The stronger
signed-size check implies `5C+400 < INT_MAX/4`, below `SREAL_MAX_EXP`.
Positive terms stay above 2^-64; zero uses sreal's explicit zero encoding.
Normalized significands use at most 30 magnitude bits: addition,
multiplication and division's 31-bit shift fit signed 64-bit intermediates.
Exponent additions/subtractions and normalization shifts fit signed int
(`sreal.h:23–29,201–279`; `sreal.cc:154–277`). No growing time vector or
integer time-accumulator allowance is hidden in the GGC delta.

### Whole-unit shape and returned delta

The established IPA schedule's disabled gates remain disabled. Active
visibility/reachability sees at most `C+4` symbols; only its reachable set
grows. Bounds initializers have no outgoing references, and call edges lead
only to the two external callees. The single-user pass visits each bounds
node once and inserts at most C map entries: only Main refers to it and there
is no alias or variable-reference cycle (`ipa.cc:1464–1553`). Both COMDAT maps
are ordinary; charge `16*prime(max(251,2*(C+4)))` bytes each even though the
second remains empty. No COMDAT group is present, so execution returns before
propagation (`ipa-comdats.cc:235–297`). This conservative request ceiling
avoids depending on whether an individual bounds symbol is already classified
as a fixed-section symbol. The ODR map has zero entries and retains its
ordinary 128-byte control/248-byte initial backing.

Inline ordering has at most three function pointers, with two 24-byte order

### GGC constructors and vector normalization

`init_tree_ssa` creates one `gimple_df` (at most 256 raw bytes), a default-def
hash control (128), its 31-pointer backing (248), and the initial SSA-name
vector (`tree-ssa.cc:1214–1221`). `init_ssanames` requests 50 slots and reserves

(`tree-ssanames.cc:351–420`; `tree-dfa.cc:356–366`). The default-definition

small table without an `empty_slow` replacement. Its control contributes one
singleton finalizer; names, backing and the slab list do not register others.

The name vector receives at most u pushes after its initial allocation, so
there are at most **z backing requests**. A growing existing vector has its
old capacity below the desired length z. The requested capacity before GGC
rounding is bounded by `max(50,2z)`; `3z<=UINT_MAX` protects the actual
`alloc*3/2` intermediate (`vec.cc:150–170`). Define

```text
V = next_power_of_two(8 + 8*max(50,2z));
normalized_capacity = (V-8)//8.
```

The power-of-two bound conservatively covers `ggc_round_alloc_size`; the
allocator then derives its effective capacity from the rounded bytes before
storing it in the 31-bit prefix (`vec.h:393–424`). The callable checks that
normalized capacity, not just the requested z, and bounds each backing by V.
It checks the LP64 size product separately. This protects the per-phase
version/count interface. The global unsigned `ssa_name_nodes_created` counter
is not reset here: the result exposes u additional increments and leaves its
all-function, all-phase sum open (`tree-ssanames.cc:371,388`). The additional
DECL_UID and identifier-table insertion likewise remain inputs to shared
translation-unit counter/table composition.

Each statement has at most one virtual use and no real scalar use, so the
scanner's inline 16-entry temporary vector needs no heap growth. Persistent
40-byte use entries consume slabs of 1024, 4096 and then 16,384 bytes, with
capacities 25, 102 and 409. The strict allocator comparison is already
accounted for (`tree-ssa-operands.cc:256–364`). Thus the slab-request count is

```text
L = 1 + [u>25] + ceil(max(0,u-127)/409).
```

The corresponding bytes are `1024 + 4096*[u>25] +
16384*ceil(max(0,u-127)/409)`. Rebuilding a statement returns its old use list
to the freelist **before** requesting replacement entries
(`tree-ssa-operands.cc:424–485`), so the peak u bound still covers this scan's
rebuilds. Initial renaming changes pointers in place. No all-phase rescan
lifetime is inferred. The slab index always stays within its fixed 16,376-byte
payload, independently of how many linked slabs are needed.

The returned GGC event delta is therefore **6C+10+L**: three infrastructure
objects, z vector backings, three `.MEM` declaration/identifier requests,

growth. It is separate from the bounds-pool `5C+5` and graph `8C+33` deltas,
