## Variable graph owners, growth and lifetimes

The accepted finite domains are U≤180, V/signatures≤1,290 and E≤367.
`Build_Invocation_Graph` passes **elaborable unit count**, not construct count,
to initial capacities (`bindo-builders.adb:100–124`). It visits each construct
and relation at most once; signature/source-target deduplication can only
reduce graph vertices/edges (`bindo-graphs.adb:4930–5033`). Every assigned ID
also needs its successor: the sequencers increment before returning
(`:5760–5786`). V+1 and E+1 fit Natural; each edge-kind count is at most E.

The disjoint owner partition is:

| Container owner | Node bound | Initial bucket-size upper bound |
| --- | ---: | ---: |
| Bindo.Units elaborable units | U | U |
| Bindo.Units elaborable construct signatures | signatures | U |
| Invocation vertex attributes, signature-to-vertex, DG all-vertices (three maps) | V each | U |
| Invocation edge attributes, source-target relation set, DG all-edges (three maps) | E each | U |
| Invocation roots; DG components (two empty maps) | zero each | U |
| Per-vertex outgoing-edge sets | sum of degrees ≤ E | Create(1) per vertex, clamped to 8 |

`Initialize_Units` owns its two sets (`bindo-units.adb:255–259,410–458`).
Invocation Create owns five maps/sets plus DG, whose Create owns three
additional maps (`bindo-graphs.adb:5099–5119`, `g-graphs.adb:300–312`). Each
DG vertex **eagerly allocates** its outgoing set, including zero-degree vertices
(`g-graphs.adb:213–237`). Neither empty roots/components nor zero-degree sets
have zero allocation: Create allocates a control and minimum-sized bucket
array (`g-sets.adb:56–59`, `g-dynhta.adb:546–559`).

A dynamic hash node contains key, value, prev and next. In particular IGV's
value contains **three IDs**; IGE's value contains one ID. DG edge values have
two IDs; DG vertex values have a component ID and set handle; relation keys
have two IDs. On the selected ABI all these nodes and full dummy-bucket heads
fit **64 bytes**, including alignment. This is not a pointer-only bucket
charge. The dynamic control, including an unconstrained-array pointer and
three scalars, fits 64 bytes. The bound separately allows 32 bytes per array
for its two bounds/alignment, 64 for two coexisting arrays. Invocation control
has twenty Natural counters and seven handles, fitting 256 bytes; DG control
has three handles, fitting 64. These are source record/selected-ABI bounds,
not claims that private allocator metadata consumes those bytes.

For any map initialized with I∈1..U and holding at most D nodes, set
M=max(8,U,D). Capacity is at most **2M** and old/new bucket coexistence at most
**3M**. The actual rule doubles when the Long_Float load exceeds 1.5; the bound
uses only that no expansion is needed while count≤capacity. Thus it does not
assume exact rounding at the 1.5 threshold. Doubling and `Size-1` remain inside
the modular bucket range, well below the explicit safe-expansion limit.
Rehash moves existing nodes, allocates one new bucket array and frees the old;
it does not duplicate data nodes (`g-dynhta.adb:1003–1096,1192–1295`). Replacing
a key does not increment Pairs. Collision chain traversal is iterative.

For outgoing degrees d(v), summing `3*max(8,d(v)) ≤ 24+3*d(v)` gives at most
24V+3E coexisting bucket heads, plus E data nodes and V controls. This covers
both concentrated and dispersed edges. Ten top-level map bounds plus these
sets and both graph controls total **3,960,128 bytes** of conservatively
coexisting owned representation. Each individual request, component/count
index, byte product and iterator-lock count fits its native domain. The sum
is bookkeeping for these owners, not a process RSS estimate or RAM gate.

All fixed constructs are ordinary Z, and the accepted Main source producer
has only ordinary subprogram/output constructs. Root registration selects
only Elaborate_Body/Elaborate_Spec (`bindo-graphs.adb:5334–5349`), so roots are
empty. Augmentation's root loop performs no recursive invocation visit,
allocates no Visited set, and adds no library edge
(`bindo-augmentors.adb:140–200`). Component discovery runs on the **library**
graph only (`bindo-elaborators.adb:704–799`); the invocation component map stays
empty. No invocation list is created. Lists that belong to library component/
order work remain owned by the fixed projection below; `g-lists.Create` itself
allocates a control even if a list is empty. Invocation destructors walk
existing buckets/edges and free them without another population or recursive
traversal. Iterator nesting is fixed; the exported 2(U+V+E)+32 bound dominates
active handles/locks without relying on cumulative iteration count.

new actual-source cases, source/invocation/environment substitution rejection,
all 180 initial sizes by 1,291 native hash-growth states, concentrated/dispersed/

in this packet; other native children and required production proof/source
