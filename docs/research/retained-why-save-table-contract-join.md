## Private statistics and prover-ID search

`get_used_provers_with_stats` (`session_itp.ml:1954–1978`) creates a fresh private
prover table; each new entry owns three fresh frequency tables. None is stored
in the session, registered as a callback root, or passed to a nested save.
The global attempt iteration is read-only on this selected path. At most
`A=A_stats` callbacks run in one helper, including a failing prefix.

The private prover-table add is in the **handler** of its find catch, so that
catch cannot consume an exception from the add. Each frequency replace is
after its corresponding find/default catch. There is no outer helper catch
that retries a failed add/replace on the same private table. A higher save or
scheduling catch may continue, but cannot recover these locals; a new helper
creates new tables. Thus a signal-save escape or synchronous failure in a
private mutation abandons that table owner. A save callback cannot return
normally to an interrupted mutation. This is a source ownership fact under
the imported runtime behavior, not a no-failure premise.

Completed private resizes start with disjoint valid buckets and finish the
ordinary redistribution and tail cuts. During a failing resize the finite
first-prefix argument applies to that valid input; the discarded table is
never used for a later lookup/fold or another resize. There is no shared-input
second-rehash lane. The generic scalar-table implementation is attached through
the named source/runtime behavior relation; no new native-body check for that
implementation is claimed. At ordinary lookup/fold entry, visits and size are bounded
by the at most `A` insertion-capable callbacks. If an interrupted resize has
published temporary shared tails, that abandoned intermediate representation
may have up to `2*A` bucket occurrences; **the `A` exported below is for reached
client lookup/fold entry**, not an assertion about abandoned published roots.
The first-prefix argument supplies finite failed-resize work separately.
