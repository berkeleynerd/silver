## Shared inputs and one launch graph

The descriptor supplies source/configuration files, a complete-path envelope P,
worker count J, host page size and selected absolute ASCII path roles. The input
files' storage paths may differ from their symbolic launch paths: their actual
bytes are read and checked, then bound to each launch role. Every generated
compiler descriptor receives the same Main, naming and System bytes. A missing
or mismatched input is rejected before evaluating the conjunction.

The constructed graph has a 109-byte project root, a 113-byte native object and
binder source directory, and 127-byte binder source filenames. These are the
retained parent/binder path classes, not source-length limits. Producer phases
use `obj/gnatprove`, its `phase1` subdirectory and its `data_representation`
subdirectory. All compilers refer to the same `root/main.adb`. Phase 1's
`main~1.ali` copies to the phase 2 directory; the representation JSON and native
Main/binder object roles are separately named. Private GPR temporary names use
`GNAT-TEMP-000002.TMP` for naming and `GNAT-TEMP-000003.TMP` for mapping, under
distinct GPR process roles. The displayed ten-digit process IDs are bounding
placeholders, not required future PID values. Any positive signed-32-bit PID
fits their widths. The checker rebinds the actual four retained configuration
headers, verifies their noncomment semantic payload is unchanged, and recomputes
their extents; all remain within the 8192-byte aligned charge.

One common **48-byte TMPDIR** matches the native parent's retained width.
The producer parent used 54 bytes, and the binder compiler witness used 52;
these widths are not silently identified. GPR's successful absolute-directory
route copies/normalizes the root, appends `/GPR.<pid>`, and interns each generated
filename (`gpr-tempdir.adb:68–97,103–177,248–265`). Role counts and equality
classes stay fixed, while shortening this prefix reduces character demands.
Even with ten PID digits, the new producer names are two bytes shorter than
the retained six-digit names. The native parent's existing ten-digit temporary
name bound is `48 + 36 = 84`. Its bounded exchange/argument/path interfaces are
charged by the binder component; configuration-comment changes are checked
directly above. No project token, installed tool path or source search branch
changes. The descriptor requires normalized path spellings without quoting
characters and retains the ordinary accessible-directory premise.

The binder's source directory and full source names still have exactly 113
and 127 bytes. Only its temporary assembly-output operand becomes four bytes
shorter. GCC binds `-o` to `asm_file_name` (`common.opt:3885`), and GNAT copies
argv then skips `-o` and its operand (`back_end.adb:241–248,303–311`), so this
operand enters no GNAT name/source table. `init_asm_output` compares it with
the input filename and opens the distinct output (`toplev.cc:695–724`); the
fixed successful branch and existing no-debug/no-coverage projection are
unchanged. Recorded command-line text excludes `OPT_o` (`opts.cc:3925–3929`).
Thus the GGC/UID semantic request graph is unchanged; the ordinary copied
argv, driver temporary-name and filesystem strings are no larger. This is a
specific output-path transfer, not permission to shorten semantic source names.

This corrects an actual interface mismatch in the standalone native/datarep
fixtures: their `config.adc` launch name registers a configuration dependency,
whereas production's `.TMP` name does not (`frontend.adb:196–240`). The aggregate
retains the exact 327-byte naming content but rebinds its launch name to `.TMP`.
The older generic compiler bound safely overcharges the dropped dependency;
the separate 399-byte no-Xref native ALI specialization is used only with the
TMP/no-extra-dependency branch. No historical capture is relabeled.

The light frontend callable retains its original observation descriptor. The
aggregate evaluates that basis at the shared P, then explicitly binds the new
path roles using the frontend's existing 32-role Name_Find correction. The
canonical Main tokens, fixed System/configuration bytes, map cardinality,
options and successful file-request graph agree. Only the phase 2 options JSON's
`why3_dir` path changes. Its schema and corresponding 6P byte allowance are
unchanged. Native/datarep maps have one Main triple; light maps additionally
have System. Per-role maps are computed from the shared Main path and the
selected runtime path, rather than copied from unrelated scratch fixtures.

## Verdict and limits

The retained fixture passes the evaluated conditions with no open null-component
interface after the launch-role substitution. This is a conditional null-family
conjunction under the existing relevant-source-behavior, ABI, fixed search,
fresh-directory, path-equality and external resource/service premises. The
parent must actually materialize the computed graph; this Python research tool
is not that production launcher. Physical heap/stack/disk availability and
libc/OS internals remain the existing boundary, and no aggregate RAM gate is
introduced.

Eleven offline checks cover the retained source, uppercase/CRLF, permitted
comments above 4096 bytes, added physical lines, overflowing columns/workers/page
scratch, wrong binder path width, forbidden VT, changed syntax and mismatched
naming content. Source variants reuse successful fixed evidence. No compiler,
assembler, linker, server, solver or Lean execution ran for this packet.

The next substantive #119 dependency is the **nonnull source-to-pipeline
composition**, beginning with literal output and then the currently admitted
grammar, plus the useful admitted-domain/comparator result. Production native
SPARK/Lean counter correspondence and implementation remain later work. A closed
null conjunction alone does not complete #119 or authorize an admission change.
