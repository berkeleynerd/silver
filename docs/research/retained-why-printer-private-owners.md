## Persistent-tree height and storage operands

`Mstr` is Extmap; tagged Mty/Mts/Mls/Mid/Mvs and their Extsets are the same
immutable tree implementation (`wstdlib.ml:24,60–99`, `extset.ml:56–101`).
`info_model` instead uses the retained OCaml `Set.Make`. Neither stores a
mutable size, bucket array or growth threshold. Extmap nodes have five fields;
Set nodes four; list cells two. The information record has 25 fields. These
fixed-size node allocations have no cardinality-dependent block-size operand.

Completed empty/add/remove/map/filter/split/join/union operations preserve
correct heights and child-height difference≤2. Pure failed operations publish
no replacement tree. A tree of height h has at least
`2^floor(h/3)-1` nodes: at every third level both descendants have the preceding
level's height. Thus `3*bit_length(n+1)+4` bounds height and temporary
join/rotation height operands for an n-node envelope; the packet uses an extra
two-input envelope when applying it. `height+1`, `height+2` and comparisons
therefore fit. `set_disjoint` also creates temporary zero-height comparison
views; they are never published or passed to height arithmetic. This deliberately weak logarithmic lemma avoids equating a
mathematical node count with the stored integer height.

A point operation performs at most this height's comparisons, and at most
eight local node steps per level including rotations. For two-input operations,
the packet exports `16(n+1)²` node-step work: split/join traverse subtrees, each
ordered pair of source nodes can participate in at most a constant number of
descent/rotation steps; callback work is counted separately by the owner/helper
budgets. Filter/map/fold are at most their input traversal plus joins. These
are finite work bounds, not native loop counters. No nonempty private-tree
`cardinal` call is reached; type-variable checks use `is_empty`. Borrowed task
metadata trees retain the accepted H-node input-field bound.

The native `Mvs` value additions/products have the separate occurrence bound
above. Fixed tag comparisons use the retained first-global-violation premise;
they do not subtract potentially distant tags. Source hashes retain their
specified modular behavior. Physical stack, allocator/GC and memory sufficiency
remain trusted; this argument creates no aggregate RAM gate.
