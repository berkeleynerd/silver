# Retained Debug formatter control

The [research note](../../research/retained-why-debug-formatter-control.md)
establishes the escape formatter's constructor/setup state before first Stats
entry under the existing selected source/runtime/loader relation. It also
identifies the one additional newline wrapper and its 16-byte own frame.

- `source-witnesses.json` contains exact retained source excerpts.
- `source-client-inventory.json` is a full-projection lexical inventory; comments
  and interface matches are intentionally retained and classified in the note.
- `flag-flow.json` resolves debug-output flag names and generic print_meta clients.
- `input-attachment.json` binds five process/exit observations to the frozen
  capture manifest and accepted prefix attachment without replaying it.
- `native-bodies.json` and `native-control.json` retain selected installed witnesses.
- `result.json` exports the conditional constructor state and callback ownership.
- `inputs.json` and `round.json` record identities, scope, settings and validation.

Run `python3 docs/evidence/retained-why-debug-formatter-control-20261020/check.py`.
It reads existing source archives, five capture archives, the retained `/tmp`
disassembly and installed executable. It runs no target, capture, disassembler,
source fetch, solver, proof or predecessor checker. The semantic source/control
argument requires independent review; the checker does not prove it.

The queue initially has its one dummy box token; only the Buffer is empty.
No freshness claim applies after partial Stats output. Standard/error formatter
phases, partial-output bounds, full R and complete save/exit capacity remain open.
