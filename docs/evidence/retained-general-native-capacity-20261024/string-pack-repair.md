## Why the additional layout executes

Standard.String receives `Has_Pragma_Pack` in `cstand.adb:582–595,915–922`.
The flag is registered `Impl_Base_Type_Only` at
`gen_il-gen-gen_entities.adb:719`; `gen_il-gen.adb:1650–1659,1695–1738`
generates getters reading `Implementation_Base_Type(N)`. That helper reaches
Base_Type before its private-view handling (`einfo-utils.adb:1415–1432`).
Consequently ordinary String subtypes inherit the query result even though
the frozen Character8 representation is not bit-packed.

`Freeze_Entity` calls `Check_Compile_Time_Size` and then `Layout_Type`
(`freeze.adb:8143–8180`). The former's known-size flag does not bypass the
latter's `Has_Pragma_Pack` branch. For a constrained one-dimensional String
with static bounds, component size8 and alignment1, `layout.adb:510–553`
computes the raw extent again and, if Esize is unknown, rounds it:

```text
d = Hi - Lo + 1
s = 8*d
r = trunc_toward_zero((s + 7)/8)*8
RM_Size := s; Esize := r
```

The guards require known component/alignment fields; their direct values8/1
add no Uint allocation. UI_To_Int(Alignment)=1 and the host Int multiplication
by SSU=8 are representable. `Abits-1` is host Int7, not a Uint subtraction.
Unknown bounds fail the static-bound guard. E_String_Literal_Subtype returns
at `layout.adb:237–246` before this branch; its earlier literal-specific charge
remains valid. A separately created ordinary array subtype around a literal
still belongs to the repaired ordinary-array family.

## Local allocation, magnitude and workspace bound

Assume the existing resolved-bound premise: Expr_Value returns existing Uints
for literals/finite constant-name chains; bound analysis, capture and prior
size checking are separately charged. Let H>=1 bound both endpoint magnitudes,
and let k be the base32768 digit count of `M=8*(2H+1)+7`. One entry costs:

| Operation | Maximum new Uint entries |
| --- | ---: |
| Hi-Lo | 2: possible negation of Lo, then addition |
| +1 | 1 |
| multiply by8 | 1 |
| +7 | 1 |
| divide by8 | 1 |
| multiply by8 | 1 |
| Total | **7** |

Subtraction's direct arm needs at most one; the two-entry bound includes its
other arm (`uintp.adb:2222–2241,2156–2178`). Addition and multiplication append
at most one via UI_From_Int/Vector_To_Uint (`791–989,2010–2071`). UI_Div uses
UI_Div_Rem with `Discard_Remainder=True`; divisor8 selects its one-digit arm,
which converts just the quotient (`1001–1025,1031–1152`). It neither appends a
remainder nor enters general Algorithm_D. Small overload conversions1/7/8
return before UI_Ints lookup (`1466–1481`). Each of the at most seven result
conversions can additionally miss UI_Ints at most once: conservatively allow
seven16-byte wrappers, with the already charged fixed1023-bucket array.

Every newly appended magnitude is <=M, including a temporary negated endpoint,
raw extent, s+7, quotient and rounded result. Thus add at most **7k digit words**
and seven Uint descriptors. Components are four-byte digits and eight-byte
Uint entries; their table backing/growth must be checked separately. A k-digit
bound on the *incoming* endpoints also gives the simple safe new digit bound
k+1, since `8*(2*(32768^k-1)+1)+7 = 16*32768^k-1 <32768^(k+1)`.

There are no new AST nodes, entities, lists, names or String values. Esize/RM
field writes stay within the already charged61-slot-per-generated-entity
allowance. They are not new syntax-array or String descriptors.

Transient numeric owners and views are distinct from retained digit words:

| Selected helper | Simultaneously live UI_Vector owner payloads, in words |
| --- | ---: |
| General addition, including opposite-sign subtraction | `L+R+3*(max(L,R)+1) <=5k+3` |
| Operand negation | `<=k` |
| Multiply by8 | `k+1+(k+1) <=2k+2` |
| Divide by8 | dividend k + divisor1 + quotient k = `2k+1` |
| UI_From_Int cold result | fixed3 |

Normalization in Vector_To_Uint scans leading zeros and appends significant
digits; it does not allocate a second result vector (`2361–2433`). Init_Operand
fills its supplied vector (`457–478`). The arithmetic operations complete in
sequence; the negated Uint can remain retained while its temporary vector has
returned. The selected largest individual owner has at most `max(k+1,3)`
words. At the source numeric-helper layer, at most five owner vectors coexist;
allow six owner/borrowed unconstrained-array descriptor views (addition's
five owners plus the converter view, or division's three owners plus its two
formal views). Reserve32 bytes per view: the retained16-byte descriptor, its
two four-byte bounds, and padding headroom. Thus descriptor/bounds storage is
at most192 bytes at this source-helper layer. These are logical local-object/
descriptor bounds, **not** a complete native stack-frame bound or aggregate memory admission limit. Require
`k+1`, `5k+3` and each four-byte dimension/product plus descriptor to fit their
respective signed-index/address representations. Later lowering, caller frames,
alignment and physical stack headroom retain their existing obligations.

For d>=0, r=s exactly, so the `Esize<RM_Size` tail cannot add work. For a
superflat static range d<0, the source does **not** clamp before this formula:
r=8*(d+1), and the sizes are negative or zero; both are still bounded by M.
`Known_Static_*` requires nonnegative values, so the tail is again absent.
This covers the general reusable slice transfer without assuming all null
ranges are exactly1..0. Native validation ignores negative size requests and
zero-unspecified requests; this refines the no-padding statement in the #201
note. It does not supply a new language premise about permitted empty Strings.

## Why an entity allowance bounds layout entries

The repair charges **first layout entries**, not references or runtime trips.
The selected local array/index families reach Layout_Type via Freeze_Entity.
It tests Is_Frozen at `freeze.adb:6537–6553`, sets it before dependency recursion
at`:6809`, and performs the one ordinary layout at`:8180`. Its thaw paths are
class-wide/private/partial-view cases, absent from ordinary Main String types.
Delayed freeze creates a scheduling node; it does not clear an already-frozen
ordinary type to repeat layout. Existing subtype-copy logic may clear the
**new** copied itype's freeze state (`sem_util.adb:25278–25306`); that is a fresh
entity already included in the decorated-copy entity count.

The full retained Ada source call-site search finds the following other direct
Layout_Type callers: Standard_Exception_Type (`cstand.adb:1557`), anonymous
access types (`sem_ch3.adb:908`, `sem_ch6.adb:9511`, `exp_disp.adb:594,989`, the latter an access-to-subprogram type), protected
component/itype handling (`sem_ch9.adb:613,1955`), and the anonymous-access-to-
subprogram return-type case (`freeze.adb:8191`). None reenters a selected local
Main String array type. Source hashes and the complete matching source files
are retained in the repair source packet; this is an authored reachability
argument, not a claim that a lexical search alone proves reachability.

Therefore each eligible Main array entity contributes at most one new entry.
Let N_layout count these entities, including copied entities across lifetimes.
The established cumulative Main entity allowance gives `N_layout<=E_Main`.
Fixed imported types are a separate graph already captured/charged; this delta
does not replay or recalculate their layouts. No count of final live entities
is substituted for the cumulative bound.

## Current consumers and replacement rule

The slice-pair first-freeze transfer is now **up to7 Uint entries/7k digits**,
with all its earlier zero syntax/list/name results retained. A prior first-size
calculation of up to4 entries is a distinct earlier stage: when needed, the
combined bound is11, not7. Repeated freezing adds zero after the once-only
argument above. A known dynamic-bound exclusion may sharpen the additional
charge to zero; no such exclusion is inferred merely from the absence of a
source representation clause.

The current exported rule deliberately avoids reconstructing all old descendant
formulas. Given a historical Main constructor/logical join and its cumulative
E_Main and common incoming Uint digit bound K>=1, add exactly this conservative
repair row to the **allowance**, once:

```text
additional Uints       = 7 E_Main
additional digit words = 7 (K+1) E_Main
additional UI_Ints wrapper allowance = 7 E_Main
current common Uint digit bound = K+1
```

This is an overestimate, including non-array entities, rather than an assertion
that every entity executes layout. It covers every affected constructor/copy

N_layout may replace E_Main by that number. Do not add the per-site seven-entry
reservations on top of this global repair: they explain its coverage, not a
second additive charge. The old sums are preserved as historical subtotals;
current fields in `string-pack-current.json` contain the repaired Main and
joined Uints/Udigits values, fresh backing checks for those changed tables,
