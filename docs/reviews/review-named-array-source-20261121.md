## Finding R1 and its repair

At the initial target `4582003a5f`, the Compose proof accepted three semantic equations about arbitrary imported calls. These covered the full-table scalar reader, object lookup and named-type lookup. Knowing that native `Lookup_Type` returns 1 for a visible first declaration of type T still allowed an unrelated Compose projection to return 0 at the same cursor. The two Boolean wrappers independently assumed the predicate helpers' meanings, and their context conversions dropped the newly introduced type table. These were high-severity gaps in the proof connecting the implementation to its model. The initial review identified no unsafe admitted Ada program.

1. **Compose imports.** `ArrayImportSource` identifies both lookups with projections of one interpreted native array library. It also identifies the Compose scalar reader with the interpreted native expression reader. The reader fixes the Ada defaults for masks, signs and element mode, and retains the caller's table, initial values and elaboration flag. The three laws follow on the original domains, including zero cursors, empty tables, physical arrays and symbolic views. The root supplies the derived facts to the definition and callable builders. [Array import proof](https://github.com/berkeleynerd/silver/blob/ba0e9fee9a825f08c78c19a8993f940b36ad9a5c/proof/Silver/ComposeArrayImportMeaning.lean)
2. **Boolean initialization in Main.** Each wrapper's predicate call record now provides raw literal equations, the literal wrapper refinement and the direct library identities for that same predicate. `Predicate.Native.Libraries.helper_meaning` combines those facts with the Compose raw equations. The ordinary declaration follows the linked condition worker. Boolean aggregate recursion follows `Boolean_Initializer_Model`, to which the native executable helper is proved equal. Both context conversions retain `arrayTypes`. Object lookup receives the complete table, and type lookup receives its type component. [Boolean import proof](https://github.com/berkeleynerd/silver/blob/ba0e9fee9a825f08c78c19a8993f940b36ad9a5c/proof/Silver/ComposeBooleanImportMeaning.lean) · [Declaration lookup and worker](https://github.com/berkeleynerd/silver/blob/ba0e9fee9a825f08c78c19a8993f940b36ad9a5c/proof/Silver/ComposeBooleanDeclarationLibraries.lean)
3. **Callable locals.** Both declaration builders receive the derivation of the ordinary Boolean declaration law from raw helper equations. The root then installs the derived array and Boolean laws on the inherited calls selected by the final function source and the procedure's `helpers.ordinarySource`. The equality of the call records identifies the actual callee. `ExactDomain.state` transports the original native state, readiness and bounds requirements. This reaches the shared `Function_Locals` reader before formal input views are installed. The checked function source also covers the shared `Formal_Type_At` reader, the bounded `Type_Id` record field, and the model and ordinary bodies of `Append_Array_Parameter`. ## String and Character assurance

The String and Character initializer witnesses now retain `state.arrayNames.table` in the source parse, and the frozen store retains physical object metadata and initial values. The outer proof derives `StoredArrays` from the accepted token sequence. It carries that fact through the full declaration trace, including an array-type declaration that preserves the byte and bounds stores. The final proof change after static review supplied the complete table explicitly to two lemmas and unfolded its definition in their local results. Both public theorem statements, `source_actual_initializers_bounds` and `source_actual_string_bounds_assured`, are byte-for-byte identical to the initial integration. [Initializer proof](https://github.com/berkeleynerd/silver/blob/ba0e9fee9a825f08c78c19a8993f940b36ad9a5c/proof/Silver/PredicateStringActualInitializers.lean) · [Source assurance endpoints](https://github.com/berkeleynerd/silver/blob/ba0e9fee9a825f08c78c19a8993f940b36ad9a5c/proof/Silver/PredicateStringActualAssurance.lean)

An Integer-array actual carries its type identity and descriptor, so its String expression bounds property is immediate for both a function input and a procedure value input. The ordinary array checker still enforces nominal identity, shape and component ranges. A Boolean actual paired with an array formal fails the ordinary type check. The mathematical call argument captures cells in index order, derives disjoint input segments and preserves scalar writable-target separation. Array-type declarations keep both bound-expression obligations, and checks for every declared callable include unused declarations.
