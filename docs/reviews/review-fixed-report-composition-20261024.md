critical checks behind that conclusion, rather than an inference from a small
observed report.

   requires an analyzed SPARK body for a subprogram but an analyzed SPARK

   retain a graph. The callable census 3/5/1/1 is separate from both frontend
   allocation and metadata domains. The six fixed sources and accepted light

   Runtime's single abstract state takes the one initial/final pair at

   ignored by `Process_Statement_List`; nonflow pragmas generate one null
   vertex each. Absent initializer/condition and list joins fit the stated
   surplus. Consequently A_frontend+12 covers construction, including the
   later-cleared nodes, without promoting raw list-header counts.

   I checked the important surviving-flag exception: `Clear_Vertex_And_Attributes`
   preserves `Is_Original_Program_Node`, and `Find_Dead_Code` can emit from it.
   `Null_Attributes` initially clears that flag; the sole assignment in
   `Prune_Dead_Paths` excludes `Is_Null_Node and Is_Program_Node`. The selected

   Simplification precedes the saved `Full_CFG`/`Full_Atr`, so restoration does

   The trace roots likewise cannot reach the isolated cleared vertices.
