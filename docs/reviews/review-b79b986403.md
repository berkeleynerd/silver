# Bounded mutable integers milestone review — `b79b986403`

Independent review of the completed Bounded mutable integers milestone,
[PR #76](https://github.com/berkeleynerd/silver/pull/76), on Linux x86_64
(`linux-x86_64`, host `claude-silver`, 22 CPUs, 31 GB RAM, no swap), 2026-10-17.
This is a review only. No implementation, issue, board, harness-goal or Git
state was changed. This report is untracked.

## Verdict

**Not yet clean: one blocker must be repaired before the capability fully
meets the Oracle, and before the next construct builds on it.**

- **B1 (blocker).** Silver admits some scalar assignments inside loops whose
  index interval is empty, and the pinned GNAT 16.1 frontend rejects those
  programs. Under the mandatory `pragma SPARK_Mode (On)`, GNAT reports its
  compile-time range error ("value not in range ... Constraint_Error would
  have been raised at run time") as a hard error. `silver compile` then fails
  with exit 3. This breaks "A program expressed as valid Silver can never be
  rejected."
  - Three reviewers found it independently.
  - The lead reproduced it end to end and mapped its scope.
  - A differential fuzz found it in 74 admitted programs and found no other
    frontend-legality mismatch in 3,137 admitted programs.
- **M1 (medium assurance gap).** The Lean declaration model copies each
  object's declared range from the recognizer model's own output. It has no
  independent semantic reading of the `range L .. U` endpoints. A shared
  mistake in the native recognizer and its Lean mirror could therefore escape
  every theorem. The current code computes the correct bounds.
- **Documentation and records.** Six low and nine info-level inaccuracies,
  mostly stale pre-completion wording, plus five optional improvements.

**What held up.**

- **Execution semantics.** Bounds are captured at loop entry, writes persist,
  only the index is restored, snapshots behave as specified, and the store is
  threaded through both checked and ordinary execution. Native execution and
  the Lean model agree.
- **Staticness.** Known declaration values are kept separate from
  Ada-staticness, and mutable reads use the full declared range without
  narrowing.
- **Report envelope.** 15,292,416 bytes, leaving 1,484,800.
- **Operator budget.** It holds, including the earlier `N1E+1` repair.
- **Proof hygiene.** No project axioms, `sorry` or `native_decide`.
- **Correspondence.** Certificates and source pins match the delivered source.
- **Validation integrity.** Every recorded result reconciles with retained
  artifacts and git objects.
- **Tracking.** Milestone, issue and Rosetta tracking is consistent apart from
  the stale wording noted below.

**Repair priority before the next construct.**

- **B1:** required.
- **M1:** recommended in the same repair, because it touches the same
  declaration and assignment proofs.
- **Documentation items:** batch them with the repair's record update.
- **Optional improvements:** at the owner's discretion.

## Findings by severity

### B1 — Blocker: admitted vacuous scalar assignments in empty loops fail the pinned GNAT frontend

**Locations.**

- [src/silver_output_profile.adb:1380-1386](../../src/silver_output_profile.adb#L1380):
  `Scalar_Assignment_Body` skips the target-range test when
  `Scalars.Is_Empty (Value.Bounds)`.
- [proof/Silver/IntegerMutable.lean:16-17](../../proof/Silver/IntegerMutable.lean#L16)
  (`Interval.included := source.isEmpty || …`), used by `Assignment.check`
  at [:123-127](../../proof/Silver/IntegerMutable.lean#L123).
- [language.md:261-262](../../language.md#L261) and
  [:432-436](../../language.md#L432).
- [docs/bounded-mutable-integers.md:114-117](../bounded-mutable-integers.md#L114).
- [catalogue/silver.json:691](../../catalogue/silver.json#L691) and
  [:733](../../catalogue/silver.json#L733), with
  [src/silver_catalogue.adb:729](../../src/silver_catalogue.adb#L729) and
  [:771](../../src/silver_catalogue.adb#L771).
- [tests/test_mutable_integers.py:82](../../tests/test_mutable_integers.py#L82).

**Violated rules.**

- **Oracle.** "A program expressed as valid Silver can never be rejected. If
  it compiles, it proves." Also: "Rejection or proof failure of a valid Silver
  program is an implementation defect."
- **Frontend premise.** [docs/trusted-boundary.md:54](../trusted-boundary.md#L54)
  states the pinned-frontend acceptance premise, and the bracket-literal
  paragraph after it shows the established practice of restricting admitted
  bytes to what GNAT accepts.
- **Lean `ToolContract`.** The `parseCompletes` and `buildCompletes` premises
  ([proof/Silver/Current.lean:210](../../proof/Silver/Current.lean#L210),
  [:220](../../proof/Silver/Current.lean#L220)) behind `automatic_pipeline`
  are false for these sources.

**Reproduction (lead, end to end).**

```ada
with Silver_IO;
procedure Main is
   pragma SPARK_Mode (On);
   A : Integer range 0 .. 9 := 0;
begin
   for I in 20 .. 10 loop A := I; end loop;
   Silver_IO.Put_Line (Integer'Image (A));
end Main;
```

`silver check` prints `Accepted: silver.` (exit 0). `silver run main.adb`
exits 3 after 0.89 s (workspace `program-dGO3X5`) with:

```text
error: value not in range of subtype of "Standard.Integer" defined at line 4
gnatprove: error during generation of Global contracts
Verification failure for admitted Silver: toolchain or implementation defect.
```

A second case fails the same way (exit 3, `program-VoUEAf`). It has non-static
emptiness: `N : Integer range 0 .. 9 := 0; A : Integer range 0 .. 9 := 0;` and
the loop `for J in 10 .. N loop A := J; end loop;`. Plain
`gcc -c -gnatc -gnat2022 -gnato -gnata` with the pinned GNAT gives the same
error, so `gprbuild` would fail too.

**Mechanism.** Silver gives the index an empty interval (here `[20,10]`, or
`[10,9]` for `10 .. N`). Every index-dependent RHS interval is then empty, and
both the native rule and Lean `Interval.included` treat an empty RHS as
included in the target.

GNAT's `Analyze_Assignment` calls `Apply_Scalar_Range_Check`
(retained `tmp/frontend-capacity-20261016/sem_ch5.adb:1031`), and
`Determine_Range_To_Discrete` (`checks.adb:3395-3436`) returns the loop
parameter's inverted bounds. When the RHS range computed from those bounds
lies wholly outside the target subtype, GNAT calls `Bad_Value`, which raises a
compile-time constraint error. `sem_util.adb:6048` sets
`Error_Msg_Warn := Warn or SPARK_Mode /= On`, so under SPARK_Mode (On) the
message is an error. `Is_Statically_Unevaluated` (`sem_eval.adb:5818`) does
not exempt loop bodies.

**Scope.** The lead's sweep used the pinned GNAT semantic check plus two end-to-end runs.

| Case | Silver | GNAT |
| --- | --- | --- |
| Statically null `20 .. 10`, `A := I`, target `0 .. 9` | admitted | **error** |
| Statically null `1 .. 0`, `A := I`, target `5 .. 9` | admitted | **error** |
| `1 .. 0` or `9 .. 0`, target `0 .. 9` (inverted range overlaps target) | admitted | accepted |
| `10 .. N` with `N` in `0 .. 9` | admitted | **error** (end-to-end exit 3) |
| `2 .. 1`, `A := (I * 100)` | admitted | **error** |
| `20 .. 10`, `A := (I * 0)`, target `1 .. 9` | admitted | **error** |
| `reverse 20 .. 10` | admitted | **error** |
| Assignment inside an `if` arm in the empty loop | admitted | **error** |
| Static named-constant bounds `L .. H` with `L = 20`, `H = 10` | admitted | **error** |
| Inner `for J in 5 .. I` inside `for I in 1 .. 2`, target `0 .. 3` | admitted | **error** |
| Unconstrained target, `for I in 1 .. N` with `N` in `-5 .. 0`, `Y := (I + 2147483647)` | admitted | **error** ("not in range of type Integer") |
| Pre-existing forms in the same empty loops: Image output with definite overflow, comparison, inner loop bound, String Image assignment | admitted | accepted (warning "loop range is null") |
| Dead branches that GNAT could narrow (`if X = 20 then Y := X`, `X range 0..9`), 11 variants | admitted | accepted |

**Differential fuzz (lead).** A grammar-based generator produced 8,100 random
static-shell programs from Integer objects, static ranges, scalar and String
assignments, conditions, nested and reverse loops, and Image output.

- Silver admitted 3,137. GNAT's semantic check rejected 74 of those.
- An oracle tested each failing assignment `T := RHS` by rewriting it as
  `T := ((((RHS) * 0) + 2147483647) + 1)`, which Silver admits only if RHS's
  interval is empty. All 74 failures were vacuous empty-interval scalar
  assignments.
- No other kind of frontend rejection of an admitted program appeared.

**Formal confirmation.** Lean probe `NullLoop.lean` (written by reviewer R3,
re-run by the lead, 6.7 s) proves `Current.accepts c1 = true` by
`decide +kernel` for the first reproduction. It also proves that a meaning
exists whose obligations all discharge, using only `propext`,
`Classical.choice` and `Quot.sound`. The Lean endpoints therefore assert
assurance for a source the pinned toolchain cannot compile, relying on
`ToolContract` premises that are false here.

**Impact and scope.**

- Every shell is affected.
- It is a closed failure: no wrong output and no runtime misbehavior.
- Execution safety and the Lean model are sound, because such a loop never
  iterates.
- PR #76 introduced the defect. Before it, Integer objects were immutable and
  there were no Integer assignments. The pre-existing vacuous forms (Image,
  comparison, loop-bound and String contexts) still compile, as do 14 of the
  16 native compiles reviewer R2 ran.

**Why validation missed it.** The only empty-loop regression,
`for I in 9..0 loop A:=I;end loop;` at `tests/test_mutable_integers.py:82`,
is admission-only. GNAT accepts it because `9..0` overlaps `0..9`. No retained
compile contains an index-dependent assignment whose inverted range misses its
target.

The capability record's "empty-loop legality" probes
([docs/bounded-mutable-integers.md:293](../bounded-mutable-integers.md#L293))
checked Silver's own rules, not GNAT acceptance. The same hazard class was
found for String assignments in review-4503d17 B1 (also a blocker). It led to
the dead-arm rule at [language.md:425-426](../../language.md#L425), which was
not carried over to scalar assignments.

**Counterevidence considered.**

- Statically null loops whose inverted range overlaps the target compile, so
  not every vacuous assignment fails.
- GNAT accepts all 11 admitted dead-branch variants and the pre-existing
  overflow/Image/String forms.
- GNATprove discharges vacuous checks in non-static empty loops that GNAT does
  not flag (R2 probe `program-uJV8st`).
- No pipeline step rewrites or tolerates this error: build and proof both use
  the byte-identical `main.adb`.
- Reviewer R2 reported "no error for statically null loops". That holds only
  for inverted ranges that overlap the target and is corrected by the matrix
  above.

**Recommended repair.**

- **Option A (recommended).** Require a non-empty RHS interval for every
  Integer assignment.
  - Native: remove the `not Scalars.Is_Empty (Value.Bounds) and then` escape in
    `Scalar_Assignment_Body`, so an empty RHS is rejected.
  - Lean: change `Assignment.check` to require `!value.isEmpty` with inclusion,
    and update the scalar-assignment helper and source correspondence.
  - Specification and records: update `language.md:261-262` and `:432-436`,
    the capability record `:114-117`, and both catalogue sources. State the
    restriction's purpose: the pinned frontend checks statically known ranges
    in dead loop bodies under SPARK_Mode (On).
  - Tests: flip `tests/test_mutable_integers.py:82` to expect rejection.

  **Why it suffices.** GNAT's loop-parameter range can only be inverted when
  `Lo(low) > Hi(high)`. Silver's bound intervals are at least as precise, so
  `a ≥ Lo(low)` and `d ≤ Hi(high)`. Hence a GNAT-inverted index implies a
  Silver-empty index. Conversely, when Silver's RHS interval is non-empty,
  every GNAT operand range is non-inverted and contains Silver's interval. The
  RHS range GNAT computes then contains a non-empty interval inside the target,
  so `Bad_Value` cannot fire. All 74 fuzz failures fall in the rejected class.
- **Option B.** Replace each empty index interval with a GNAT-conservative
  non-empty surrogate, such as the hull of its bound intervals, when testing
  assignment containment. This admits more dead code but ties admission to
  GNAT's `Determine_Range` heuristics. It is more fragile and not recommended.

**Proportionate verification.**

- `silver check` returns 2 for every reproduction in the matrix.
- Add compile-level regressions, not only admission checks: c01, `10 .. N`,
  nested, reverse and unconstrained-overflow. Show that the vacuous Image,
  String and comparison forms and the remaining admitted empty-loop programs
  still compile.
- Run a `gcc -gnatc` sweep over the matrix, and optionally rerun the fuzz
  harness (`tmp/review-b79b986403-evidence/fuzz/fuzz.py` and `classify.py`).
- Run focused Lean checks of `IntegerMutable` and its dependents with a fresh
  axiom audit, plus the targeted native proof of `Scalar_Assignment_Body` with
  its source pin.
- This is a language change, so the normal integrated checkpoint (complete
  native audit, complete Lean run, full suite) applies once, at the repair's
  stable inputs.
- Update the capability record's disposition. Its completion claims (e.g.
  [docs/bounded-mutable-integers.md:3](../bounded-mutable-integers.md#L3),
  `roadmap.md:19`) currently cover these programs.

### M1 — Medium: declared ranges have no independent semantic reading

**Locations.**

- [proof/Silver/ComposeScalarDeclarations.lean:97-103](../../proof/Silver/ComposeScalarDeclarations.lean#L97):
  `ScalarDeclarationAt.declaration` builds
  `⟨value, parts.constraint.bounds, decide (parts.constantAfter = 0)⟩`.
- [:13-23](../../proof/Silver/ComposeScalarDeclarations.lean#L13):
  `ScalarDeclarationReady` relates the constraint only through
  `after ≠ 0` and inclusion of the initializer value.
- [:47-72](../../proof/Silver/ComposeScalarDeclarations.lean#L47):
  `scalarConstraintAt_bounded` obtains readings of `L` and `U` via
  `read_sound` and discards them.
- [proof/Silver/ComposeAdmission.lean:377-388](../../proof/Silver/ComposeAdmission.lean#L377)
  (the recognizer-model `scalarConstraintAt`).
- [proof/Silver/IntegerDeclarations.lean:32-42](../../proof/Silver/IntegerDeclarations.lean#L32)
  (consumers of `Declaration.bounds`).

**Violated rules.**

- **Oracle.** "Lean proofs must establish correspondence between their formal
  models, the actual SPARK compiler … and the authoritative Ada/SPARK source."
  Also: "Proving a separate model alone does not establish implementation
  correctness."
- **Capability record.** The assurance row at
  [docs/bounded-mutable-integers.md:177](../bounded-mutable-integers.md#L177)
  says the declaration layer specifies range inclusion.
- **Specification.** [language.md:210-225](../../language.md#L210) defines the
  range by its source endpoints.

**Reasoning.** Every other scalar position is tied to an independent
`ScalarExpression.At` reading of an `Integer.Expr` with Ada evaluation: the
initializer, the assignment RHS
(`PredicateBasicReadings.lean:37-38`), loop bounds and conditions. Declared
bounds are not. The lead's search of all non-certificate Lean sources found
only cursor validity, boundedness and initializer containment for
`scalarConstraintAt`. The trace theorems (`scalar_declarations_declared_bounds`)
carry only boundedness.

Suppose a coordinated mistake made native `Scalar_Constraint_At` and its Lean
mirror return wider but bounded bounds, for example `Interval.full` on success.
Every theorem statement would survive with trivial proof edits, while GNATprove
would check against the true Ada subtype. Admitted programs such as
`A : Integer range 0 .. 9 := 7; … A := 100;` would then fail proof. The
end-to-end claim would rest on a faithful-generation premise that is silently
false.

**Impact.** No current misbehavior. The native and Lean code compute
`(eval L, eval U)`. Seven R4 endpoint probes, the lead's probes and
`tests/test_mutable_integers.py:29-54` agree with Ada. The gap is in the
independence of the universal argument, which is the review brief's
"shared-mistake" concern.

**Counterevidence.** Model/native equality (`interpreted_scalarConstraint`)
is proved. The other parser-defined field, `mutable`, is a trivial
keyword-presence fact. Staticness does not enter the safety semantics.

**Recommended repair.**

- Prove `scalarConstraintAt_sound` with two cases:
  - Absent `range`: the bounds are `full`.
  - Present `range` with `after ≠ 0`: there exist `low`/`high` with
    `ScalarExpression.At` readings at both cursors, `isStatic` true, singleton
    inference, and `bounds = ⟨low.evaluate s, high.evaluate s⟩` with
    `low ≤ high`.
- Then either carry the endpoint expressions in `Integer.Declaration` or use
  the lemma in `scalar_declaration_checked`/`_objects`.
- Update `docs/bounded-mutable-integers.md:177` and
  `docs/assurance.md:103-109`.

**Verification.** Focused Lean checks of `ComposeScalarDeclarations`,
`ComposeScalarTrace`, `SequenceScalarTrace` and the `Integer.Declaration`
consumers, with a fresh axiom audit. No native change is needed. Complete Lean
validation can share B1's checkpoint.

## Area conclusions

### 1. Language and admission

Specification, catalogue and native compiler agree for every new rule. This
was checked by reading and by about 345 targeted admission probes across the
lead and five reviewers, with GNAT legality checks on every admitted
non-vacuous case.

- **Visibility and hiding.** Correct: an index hiding a mutable object,
  objects hiding use-visible operations, a String or index named `Integer`,
  and `Silver_Arguments` in the static shell.
- **Staticness.** Silver's static flag is "constant with a static
  initializer". Nominal subtypes are always static, so this agrees with RM 4.9.
  Constants copied from mutable objects are exact snapshots but not static.
- **Arithmetic.** Bound and initializer overflow, null ranges and
  out-of-range initializers are rejected.
- **Body reads.** Mutable reads use the full declared range in every position.
- **Assignments.** They reject constants, indexes, hidden outer objects and
  type mixing, including in empty loops.
- **Excluded forms.** 63 accidental-admission forms are all rejected.
- **Report policy.** Scalar assignments select the assignment policy.
- **Exception.** B1.

### 2. Loop and composition semantics

R2 ran 16 native compiles, 14 of which compiled. The lead ran one. All
successful compiles printed exactly the predicted bytes and proved every
emitted check.

- **Covered behavior.**
  - Bounds captured at entry in forward, reverse and nested loops, including
    at `Integer'First`/`'Last`.
  - Writes persisting across iterations, zero-iteration loops and after loops.
  - Snapshot constants and Images, branches, short-circuit conditions,
    Put/Put_Line, and argument-shell Reject followed by assignments.
  - Nonlinear products over snapshot-derived values.
- **Diagnostics.** Only the classified advisories appeared.
- **Lean execution.** `Predicate.Execution` threads both stores, evaluates
  bounds in the entry store and restores only the index cell. This is
  faithful to Ada.

### 3. Universal assurance

The top-level endpoints quantify over every admitted program, including
mutable and constrained declarations and scalar assignments in every
statement position:

- `Program.scalar_execution_invariant`, `execution_sound` and
  `all_obligations_discharge`
- `Sequence.scalar_tokens_objects`
- `Predicate.form_reading_valid`
- `Current.admitted_assurance`, `automatic_pipeline` and
  `executable_main_correct`

Validity and agreement are derived, not assumed. `#print axioms` shows only
the three standard axioms. There is no `sorry`, `native_decide`, `extern` or
opaque bypass. Exceptions: B1, where the frontend premise is false, and M1,
the specification-independence gap.
