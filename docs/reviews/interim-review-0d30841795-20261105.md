## B1: Extreme null-slice equality gives wrong answers (new in #307)

```ada
with Silver_IO;
procedure Main is
   pragma SPARK_Mode (On);
   T : constant String := "xy";
   A : Integer range 2147483646 .. 2147483647 := 2147483647;
   B : Integer range -2147483648 .. -2147483647 := -2147483648;
begin
   if T (A .. B) = "ab" then
      Silver_IO.Put_Line ("EQ");
   else
      Silver_IO.Put_Line ("NE");
   end if;
end Main;
```

**Observed:** `Accepted: silver.`, `Success: all checks proved (67 checks).`, prints `EQ`, rc 0.
**Required:** `NE`. The slice is null and the literal is not (RM 4.5.2; `language.md:947`). A control with `A range 1 .. 3 := 3` and `B range 0 .. 2 := 2` prints `NE`.

The same defect has worse forms, all with proof passing:

- **Crash:** `A : Integer := 0;` and `B : Integer := 0;` as two declarations, with `A := 2147483647; B := -2147483648;` in the body, raises `STORAGE_ERROR`. The combined form `A, B : Integer := 0;` is rejected at the target for a different reason, so it wouldn't pin B1 either.
- **A proved check fails at run time:** with `with Silver_Arguments;` added, `D : constant String := Silver_Arguments.First_Or_Default ("");` as the first declaration (`language.md:223-224`), then the declarations above and `S : String := "abc";`, the body below, run with argument `abcdefg`, raises `CONSTRAINT_ERROR : main.adb:13 length check failed`. GNATprove had discharged that length check.
  ```ada
  if Silver_Arguments.Input_Is_Valid then
     if T (A .. B) = "ab" then
        S := D;
     end if;
     Silver_IO.Put_Line (S);
  else
     Silver_Arguments.Reject;
  end if;
  ```
- **Output on invalid input:** the body below, run with arguments `a b`, prints `unexpected` with status 0. `language.md:1145-1146` forbids this. Add `with Silver_Arguments;`, and make `Arg : constant String := Silver_Arguments.First_Or_Default ("uvw");` the first declaration, ahead of the declarations above. With either argument declaration placed later, the target rejects the program for a different reason, so a rejection regression wouldn't pin B1.
  ```ada
  if T (A .. B) /= "ab" then
     if Silver_Arguments.Input_Is_Valid then
        Silver_IO.Put_Line (Arg);
     else
        Silver_Arguments.Reject;
     end if;
  else
     Silver_IO.Put_Line ("unexpected");
  end if;
  ```

**Mechanism:** `src/silver_output_profile.adb:698-703` admits the slice and keeps its bounds (`:713`). For a constant-length operand, GNAT's array equality compares `ub - lb` in 32-bit Integer (`gcc/ada/gcc-interface/utils2.cc:368-383` at GCC `6afcc4f6da`). Let `s = lower - upper`. The comparison goes wrong exactly when `s = 2**32 - n + 1` against a constant-length operand of length `n` in `2 .. 4096`.

**Scope:**
- The endpoints must be nonstatic or fold unfavourably. Copies and concatenations carry the bounds.
- Comparison with `""` and with dynamic-length operands is correct.
- Both admission branches reach it, including `a >= B and d <= E` with one-sided guards.
- The Lean model is right and no theorem is formally contradicted. The run-time meaning and the build premises fail: reading `tools.execute` as the native run, `compilationPreserves` at `proof/Silver/Current.lean:247-250` is false for this program.
- `-gnatdM` exposes the straight-line forms but is not the cause. Other forms, and a pure Ada program, fail without it.

**Candidate repair:** one conjunct in the rejection at `src/silver_output_profile.adb:698-703`, covering both branches:

```ada
or else Scalars.Wide (Low.Bounds.Upper) - Scalars.Wide (High.Bounds.Lower)
  > 2 ** 32 - Scalars.Wide (Max_Source_Length)
```

I recommend this limit because it rejects only what can go wrong: at or below it, the wrapped difference is at least 4096, which no admitted operand length can match. The simpler limit, `> Scalars.Maximum`, needs no capacity argument but rejects more programs. Use it if the sharp limit proves awkward. Don't exempt literal endpoints.

**Tested (admission only):** with the sharp limit, all wrap reproducers are rejected, ordinary null slices stay admitted, spread `2**32 - 4096` is admitted and correct natively, spread `2**32 - 4095` is rejected, and all 59 samples are unchanged. Separately, 153 failing matrix programs are rejected under both limits.
**Not tested:** proof of the sharp limit (GNATprove on `Indexed_At` passed only for the `Scalars.Maximum` limit, 33 checks), downstream Lean, certificates, the suite.

**Also change:** `proof/Silver/StringIndexing.lean:57-60` (`sliceCheck_singletons` then needs a hypothesis), `proof/Silver/ComposeIndexedReading.lean:37,158`, `language.md:733-738`, `catalogue/silver.json:1302-1303`, `src/silver_catalogue.adb:1340-1341`. State the purpose as a pinned-GNAT restriction near `docs/trusted-boundary.md:86-91`.

**Regressions:** the forms above as rejections; both sides of the limit using `Lo := 2147483647` with `Hi := -2147479553` (admitted, prints the false branch) and `Hi := -2147479554` (rejected); `S (2147483647 .. 2147483646)` and `S (0 .. -1)` still admitted.

## B2: Slices under contradictory guards fail the native build (new in #307)

```ada
with Silver_IO;
procedure Main is
   pragma SPARK_Mode (On);
   Message : constant String := "abc";
   Count : Integer := 3;
   Last : constant Integer := Count;
begin
   if Last > 3 then
      Silver_IO.Put_Line (Message (4 .. Last));
   end if;
   Silver_IO.Put_Line ("end");
end Main;
```

**Observed:** `Success: all checks proved (67 checks).`, then `main.adb:9:38: error: static range out of bounds of subtype of "Standard.Integer" defined at line 4`, `Constraint_Error would have been raised at run time`, `Compilation failure for admitted Silver: toolchain or implementation defect.`, rc 3.
**Required:** prints `end`.

Other forms, each admitted and proved, then rejected by the native build:

| Form | Key lines | Message |
|---|---|---|
| Length | `X : Integer := 2; K : constant Integer := X; T : String := "xy";` then `if K = 0 then T := S (1 .. K); end if;` | `wrong length for array` |
| Concatenation | Same with `T : String := "xyz";` and `T := S (1 .. K) & "z";` | `too few elements` |
| Foreach element | `subtype P is Integer range 5 .. 9; A : constant array (1 .. 2) of P := (5, 6);` then `for K of A loop if K = -5 then Put_Line (S (K .. -1));` | `static range out of bounds` |
| Nonstatic loop index | `N : constant Integer := X;` then `for K in N .. 9 loop if K = -5 then Put_Line (S (K .. -1));` | `static range out of bounds` |
| Static loop index | `for I in 1 .. 9 loop if I <= 8 and then I >= 6 then if I = 2 then Put_Line (S (I .. 5));` | `static range out of bounds` |

**Mechanism:** Silver keeps the incoming interval when a guard is contradictory and never refines constants. GNAT still records the guard on the endpoint, and `Compile_Time_Compare` reads it (`sem_eval.adb:1688`; `-gnatdM` doesn't gate this). `Not_Null_Range` (`checks.adb:10994`) or the length fold (`sem_attr.adb:9947-9965`, `checks.adb:3595`) then reports a constraint error, and `SPARK_Mode (On)` makes it a hard error (`sem_util.adb:6048`). GNATprove disables this route (`exp_util.adb:7629`), so proof passes first. This is what `docs/bounded-string-characters.md:44-46` required the delivery to cover.

**Scope:**
- **Affected:** nonstatic constants, loop indexes, foreach elements and snapshots of mutable array elements. Spellings `(K)`, `(K + 0)`, `(K * 1)`, `(K / 1)`, `(0 + K)`, `(1 * K)` and `(K - 0)` all fail.
- **Not affected:** assigned mutable endpoints, static constants, endpoints spelled `(K + 1)`, `(K - 1)` or `(+K)`, and constants whose declared range decides first.
- **Not only always-null slices:** the length form uses an in-prefix slice.
- `gcc -gnatc` passes all of these, so only a full build shows the failure.
- Removing `-gnatdM` is not a repair: many failures remain and the #284 source breaks again. Keep the flag.

**Repair: not decided. Hold B2.** An earlier revision of this report recommended the native-only pragma described below. The reviewer has withdrawn that: the pragma stops GNAT's complaint from being fatal and leaves the mismatch in place, and it was only ever tested against one crude admission rule. The reviewer now prefers a guard-based admission rule, which hasn't been built, and has proposed prototyping it against the failing programs this review collected. The owner hasn't decided on the prototype or the route, so don't implement either yet.

**Preferred route, not built: a guard-based admission rule.** When Silver can show a guard outcome impossible, treat that arm as dead and reject slices in it.

- **Why it should work:** only dead arms can fail. A known out-of-prefix endpoint means Silver admitted the slice as `a > d`, and a true guard can't then imply it is nonnull. The length forms need a guard that contradicts Silver's exact length. The failing guards compare the name with a compile-time-known threshold, and Silver can evaluate most of those too.
- **Where it must look:** compare the intervals of both whole operands, not names, because `(K + 0) = -5` fails too. Cover `then`, `elsif` and `else` arms, `not`, reversed operands, parentheses, and every conjunct of `and` and `and then`. GNAT uses the first conjunct that compares the name with a known value (`exp_util.adb:7525-7532`), so with `X` mutable, `if X = 5 and then K = -5 then` fails too. This is a new check: refinement today handles only bare names against Ada-static singletons (`language.md:365-372`).
- **What it costs:** only slices in provably dead arms. By inspection, no sample, Rosetta program or admitted test has a slice in an `if` arm at all, so the repository would lose nothing. Other programs would: dead-arm slices with mutable or static-constant endpoints, and slices such as `S (1 .. 2)` under a contradictory guard on another name, are admitted and build today, and would be lost if the rule covers every slice. Limiting it to immutable endpoints would bring back the name analysis it's meant to avoid.
- **What it keeps:** GNAT's hard error stays as an alarm, so a case the rule misses still fails loudly. `language.md:549-553` already takes this kind of approach for subscripts, and the B3 and B5 candidates do too.
- **Known obstacles:**
  - With `X : Integer := 5; K : constant Integer := X;` and `Z : constant array (1 .. 2) of Integer := (-5, 6);`, the body `if K = Z (1) then Silver_IO.Put_Line (S (K .. -1)); end if;` proves, then fails natively. Silver reads `Z (1)` as a full Integer, so it can't see the contradiction. That's B3's root cause, and it needs exact reads or a conservative rule of its own.
  - `docs/scalar-guard-frontend-repair.md:64-70` argued against admission repairs. Its first objection, that an admission repair would be larger and remove useful programs, applies here too (see "What it costs" and "Work"). The others are mostly to name-based checks and static thresholds, which this is meant to avoid, but that's untested.
  - GNAT's rewrites aren't Silver's, so the rule may not close the class by itself. That's what the prototype would measure.
- **Work:** `Indexed_At` and the condition flow in `src/silver_output_profile.adb`, the matching Lean admission and certificates, `language.md:371-379,733-738` and the catalogue. Document the purpose as a pinned-frontend restriction (`oracle.md:19`), since #284 rules out silent narrowing.

**Fallback, not a repair: a native-only pragma.** It removes no proof obligation or runtime check, and `-gnatdM` set a precedent for a native-only setting. But it turns this error into a warning for every native build, and that error is how #284 and B2 were found. Issue #284 says "merely... suppressing the diagnostic, or silently narrowing the admitted language will not resolve the counterexample", and `docs/bounded-string-characters.md:56` says "no suppression" of obligations. So it would need the owner's explicit approval and a written justification: GNATprove still proves first, runtime checks stay on, and the promotion would only be lost on arms that proof shows are unreachable.

The change is in `src/silver.adb:134-135`. GNATprove never sees it.

```ada
Silver_Build.Alire_Exec & "gprbuild -P " & Shell_Directory
& "/program.gpr -p -cargs:Ada -gnatdM -gnatec=" & Shell_Directory & "/native.adc";
```

Before writing `program.gpr`, write `pragma Ignore_Pragma (SPARK_Mode);` to `native.adc`, with the same path and failure handling as the other generated files.

**Tested, pragma only:**
- All 161 admitted matrix programs and all 218 programs of a second corpus build and exit 0.
- Object code is byte-identical with and without the pragma for all 59 samples, `silver_io`, `silver_arguments` and 76 passing programs.
- A private patched driver ran the full route with rc 0 and unchanged proof counts on 13 programs.
- Five reachable-failure controls, all rejected by Silver, still raise `Constraint_Error` natively.

**Not tested, pragma:** proof of the patched `silver.adb` (a focused run hit an 18-minute cap under heavy load, which says nothing either way; the new `Write_File` call may need more prover effort), `tests/test_scalar_guards.py` against the patch, the native audit.

**What was actually tried for admission:** one coarse test rule, not keyed to guards. An always-null slice with an out-of-prefix endpoint needed two Ada-static endpoints, and fixed-target assignment rejected slices with exactly one static endpoint. It rejected 84 of 85 failures but left one admitted and failing, and lost 45 of 76 programs that build today, some with reachable arms. That says little about a guard-based rule. Two analysts proposed narrower rules for nonstatic constants and foreach elements; neither was built. One was already keyed to guards: reject a slice on such a name in an arm where a comparison on that name is impossible. The other rejected static out-of-prefix partners, and exact-length slices under contradictory guards on that name. The verifiers' runs show both scopes would miss loop indexes, and the second would also miss partners GNAT folds, such as `(X * 0)`. A verifier also found guards the first would miss: `K = Z (1)` and `(K + 0) = -5`.

**Also change, whichever route:** `roadmap.md:30-31,65-66` claim dead-code frontend rules and guard composition are preserved, which is false until B2 is repaired. `docs/evidence/bounded-string-characters-20261031/README.md:12` says the discovery packet includes "dead-code acceptance boundaries", but its dead-code cases are index-only.

**Regressions:** for every form above, an expected rejection if the repair removes it from the language, or a compile-level (full build) case if it stays admitted. ## B3: Loop bounds reading a constant array (since baseline)

```ada
with Silver_IO;
procedure Main is
   pragma SPARK_Mode (On);
   A : constant array (1 .. 2) of Integer := (5, 6);
   B : array (1 .. 2) of Integer := (0, 0);
begin
   for I in A (1) .. A (2) loop
      if I >= 1 and then I <= 2 then
         B (I) := 9;
      end if;
   end loop;
   Silver_IO.Put (Integer'Image (B (1)));
end Main;
```

**Observed:** `value not in range of subtype of "Standard.Integer" defined at line 5`, `gnatprove: error during generation of Global contracts`, `Verification failure for admitted Silver: toolchain or implementation defect.`, rc 3.
**Required:** prints ` 0`.

**Mechanism:** `Eval_Indexed_Component` (`sem_eval.adb:2664-2730`) rewrites a constant-array read with a known subscript to a literal, per element. Silver reads it at the declared component interval (`language.md:558-563`; `src/silver_output_profile.adb:4531,4533`), so a guard can narrow `I` to values disjoint from GNAT's range. `Apply_Scalar_Range_Check` (`checks.adb:3411-3435`) then reports a definite failure. `-gnatdM` has no effect.

**It fails in three different ways, so regressions must cover both routes:**
- **Positional table (above):** fails at GNATprove's frontend.
- **Single-component aggregate** (`A : constant array (1 .. 1) of Integer := (1 => 5); for I in A (1) .. A (1) loop`): proves, then fails the native build.
- **Site in a short-circuit right operand** (`for I in Window (1) .. Window (2) loop if I >= 1 and then I <= 3 and then Data (I) = 7 then`): native build passes, proof route fails.

**Scope:**
- `B (I)`, `S (I)`, constrained `X := I`, and arithmetic such as `V := (K + 5)` all fail.
- #307 adds String consumers (`C := S (I);`) but no new fold source.
- No sample or Rosetta program uses this shape. The only admitted constant-array bound in the tests is `tests/test_integer_arrays.py:99`, which has a null body.

**Candidate repair:** counted-loop bounds read mutable arrays only. In `Loop_Body` (`src/silver_output_profile.adb:4531,4533`), read both bounds with `Arrays => Mutable_Arrays (Context.Array_Names)`. This is about 25 lines in one file. Authors keep the value with `Lo : constant Integer := A (1);`, which passes the full route today.

**Tested (admission and native only):** no admitted matrix row fails natively, all reproducers are rejected, 59 of 59 samples are unchanged, and only `tests/test_integer_arrays.py:99` flips.
**Cost:** programs that compile today lose admission until rewritten, for example overlapping tables such as `Limits (5, 30)`.
**Not tested:** native proof, Lean, certificates, regressions.

**More expansive alternative, for later:** read the exact value at singleton subscripts, in bounds only. It keeps these programs (fuzz: 163 admitted, 0 failures; three full-route passes). The trial adds 8 KiB per loop frame and a third read mode in Lean. With about 159 nested loops and deepest admission already near 6.7 MiB of the 8 MiB stack, that needs its own stack work, so it doesn't belong in this round.

**Also change:** `proof/Silver/PredicateBodyAdmission.lean:258-261`, `language.md:543-545,549-553`, `catalogue/silver.json:906`.

## B5: Identity folds on an empty loop index (since baseline)

```ada
with Silver_IO;
procedure Main is
   pragma SPARK_Mode (On);
   K : Integer := 1;
begin
   K := 1;
   for I in 2 .. K loop
      Silver_IO.Put_Line (Integer'Image ((((I * 0) + 2147483647) + 1)));
   end loop;
end Main;
```

**Observed:** `Success: all checks proved (68 checks).`, then `main.adb:8:66: error: value not in range of type "Standard.Integer"`, `static expression fails Constraint_Check`, `Compilation failure for admitted Silver: toolchain or implementation defect.`, rc 3.
**Required:** builds, prints nothing, exits 0 (zero iterations). `I * 1` in the same position builds.

**Mechanism:** `Multiply`, `Modulo` and `Remainder` return `Unreachable` on an empty operand (`src/silver_scalars.ads:107,128,138`; `proof/Silver/IntegerIntervals.lean:197`; `proof/Silver/IntegerDivision.lean:239,244`; `language.md:340,358`). GNAT's expander rewrites `x*0`, `0*x`, `x mod 1` and `x rem 1` to literal 0 (`exp_ch4.adb:9842,9963,9979,10559`), and the enclosing arithmetic folds statically and goes out of range (`sem_eval.adb:6179-6217`).

**Scope:**
- **`SPARK_Mode` is not the cause here:** the same errors appear with the `SPARK_Mode` pragma removed, so B2's fallback pragma can't fix this.
